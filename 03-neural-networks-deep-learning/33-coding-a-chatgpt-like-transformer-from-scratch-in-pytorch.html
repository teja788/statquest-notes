Coding a ChatGPT Like Transformer From Scratch in PyTorch

▶ Watch on YouTube Also in: —

Josh codes a tiny decoder-only transformer, the kind of model behind ChatGPT, in PyTorch. He uses Lightning, a library that handles the training loop. The model learns to answer two prompts with the word "awesome".

In one breath

First, Josh builds a five-token vocabulary and turns two prompts and their answers into inputs and labels. Then he writes three classes. PositionEncoding adds sine and cosine values to the word embeddings. Attention computes masked self-attention with matrix math. DecoderOnlyTransformer joins all the pieces and adds a residual connection and a fully connected layer. Before training, the model answers "What is StatQuest <EOS>" with just <EOS>. After 30 epochs of training it answers both prompts with "awesome <EOS>".

The main idea

A decoder-only transformer reads a sequence of tokens and, for each token, predicts the token that should come next. A token is a word or symbol the model knows. Josh's model has only five tokens: "what", "is", "statquest", "awesome" and <EOS>, which marks the end of a sequence.

The whole model is a short chain of steps. Token ID numbers go into a word embedding layer, which turns each token into a few numbers. Position encoding adds values that tell the model where each token sits. Masked self-attention lets each token look only at itself and earlier tokens. A residual connection adds the position-encoded values back to the attention output. Finally, a fully connected layer gives one output value per possible token.

Only the outer class inherits from Lightning's LightningModule. The two helper classes inherit from nn.Module. Josh does this so the model gets everything Lightning offers without inheriting it many times.

Step by step

  1. Imports. Josh imports torch, torch.nn for the Linear and Embedding classes, torch.nn.functional for softmax, Adam for training, TensorDataset and DataLoader for the data, and lightning as L.
  2. Vocabulary. The tokens are mapped to ID numbers in token_to_id, because nn.Embedding only accepts numbers. A reverse dictionary, id_to_token, turns the output back into words.
  3. Training data. The inputs include both the prompt and the answer. Each label is the token that should come next, so the labels are the inputs shifted by one position.
  4. Word embedding. Josh lets nn.Embedding handle this step.
  5. Position encoding. The sine and cosine values are computed once and stored in a matrix, so adding them later is fast.
  6. Masked self-attention. Queries, keys and values come from three weight matrices. Then the model computes the similarities, scales them, masks them, applies softmax and multiplies by the values.
  7. Put it together. The forward pass runs embedding, position encoding, the mask, attention, the residual add and the fully connected layer.
  8. Train and generate. Josh sets up Adam, writes a training step and trains for 30 epochs, or full passes through the data. Then he generates tokens one at a time until <EOS> appears.

These are the imports at the top of the code.

import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.optim import Adam
from torch.utils.data import TensorDataset, DataLoader
import lightning as L

The training set holds two prompts, "what is statquest" and "statquest is what". Both should be answered with "awesome". Each input row contains the prompt, <EOS> and "awesome". Each label row contains the token that should come next at every position.

token_to_id = {'what': 0, 'is': 1, 'statquest': 2, 'awesome': 3, '<EOS>': 4}
id_to_token = dict(map(reversed, token_to_id.items()))

# what is statquest <EOS> awesome  |  statquest is what <EOS> awesome
inputs = torch.tensor([[0, 1, 2, 4, 3],
                       [2, 1, 0, 4, 3]])
# is statquest <EOS> awesome <EOS>  |  is what <EOS> awesome <EOS>
labels = torch.tensor([[1, 2, 4, 3, 4],
                       [1, 0, 4, 3, 4]])

dataset = TensorDataset(inputs, labels)
dataloader = DataLoader(dataset)

The PositionEncoding class builds the matrix pe once, with max_len rows and d_model columns. Josh uses d_model=2 and max_len=6 here, but real models use much larger values.

class PositionEncoding(nn.Module):
    def __init__(self, d_model=2, max_len=6):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(start=0, end=max_len, step=1).float().unsqueeze(1)
        embedding_index = torch.arange(start=0, end=d_model, step=2).float()
        div_term = 1/torch.tensor(10000.0)**(embedding_index / d_model)
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        self.register_buffer('pe', pe)

    def forward(self, word_embeddings):
        return word_embeddings + self.pe[:word_embeddings.size(0), :]

Here position is a column of positions, and unsqueeze(1) turns the sequence into a column. Setting step=2 gives the values of 2i directly. 0::2 fills every other column starting at column 0 with sine values, and 1::2 fills the rest with cosine values. register_buffer makes sure pe moves to a GPU if one is used.

The Attention class uses three nn.Linear objects for the query, key and value weights. Each is a d_model by d_model matrix with no bias, as in the original transformer paper. A Linear object stores the weights and also does the math. The forward method accepts separate encodings for q, k and v. That way the same class could also do encoder-decoder attention. There, the queries come from the decoder and the keys and values from the encoder.

class Attention(nn.Module):
    def __init__(self, d_model=2):
        super().__init__()
        self.W_q = nn.Linear(in_features=d_model, out_features=d_model, bias=False)
        self.W_k = nn.Linear(in_features=d_model, out_features=d_model, bias=False)
        self.W_v = nn.Linear(in_features=d_model, out_features=d_model, bias=False)
        self.row_dim = 0
        self.col_dim = 1

    def forward(self, encodings_for_q, encodings_for_k, encodings_for_v, mask=None):
        q = self.W_q(encodings_for_q)
        k = self.W_k(encodings_for_k)
        v = self.W_v(encodings_for_v)
        sims = torch.matmul(q, k.transpose(dim0=self.row_dim, dim1=self.col_dim))
        scaled_sims = sims / torch.tensor(k.size(self.col_dim)**0.5)
        if mask is not None:
            scaled_sims = scaled_sims.masked_fill(mask=mask, value=-1e9)
        attention_percents = F.softmax(scaled_sims, dim=self.col_dim)
        attention_scores = torch.matmul(attention_percents, v)
        return attention_scores

The DecoderOnlyTransformer class joins the pieces. The fully connected layer maps d_model values to one value per token in the vocabulary. The loss is nn.CrossEntropyLoss, because the model has several outputs.

class DecoderOnlyTransformer(L.LightningModule):
    def __init__(self, num_tokens=4, d_model=2, max_len=6):
        super().__init__()
        self.we = nn.Embedding(num_embeddings=num_tokens, embedding_dim=d_model)
        self.pe = PositionEncoding(d_model=d_model, max_len=max_len)
        self.self_attention = Attention(d_model=d_model)
        self.fc_layer = nn.Linear(in_features=d_model, out_features=num_tokens)
        self.loss = nn.CrossEntropyLoss()

    def forward(self, token_ids):
        word_embeddings = self.we(token_ids)
        position_encoded = self.pe(word_embeddings)
        mask = torch.tril(torch.ones((token_ids.size(dim=0), token_ids.size(dim=0))))
        mask = mask == 0
        self_attention_values = self.self_attention(position_encoded, position_encoded,
                                                    position_encoded, mask=mask)
        residual_connection_values = position_encoded + self_attention_values
        fc_layer_output = self.fc_layer(residual_connection_values)
        return fc_layer_output

    def configure_optimizers(self):
        return Adam(self.parameters(), lr=0.1)

    def training_step(self, batch, batch_idx):
        input_tokens, labels = batch
        output = self.forward(input_tokens[0])
        loss = self.loss(output, labels[0])
        return loss

The same position-encoded values are passed three times, once each for queries, keys and values, because this is self-attention. Josh uses a learning rate of 0.1 because it trains this small model quickly. The default of 0.001 is more common.

Generation runs the prompt through the model and keeps only the prediction made at the last token, <EOS>, using index -1. Then argmax picks the token with the largest output. Each new token is appended to the input, so the next prediction uses the full context.

model = DecoderOnlyTransformer(num_tokens=len(token_to_id), d_model=2, max_len=6)
model_input = torch.tensor([token_to_id["what"], token_to_id["is"],
                            token_to_id["statquest"], token_to_id["<EOS>"]])
input_length = model_input.size(dim=0)

predictions = model(model_input)
predicted_id = torch.tensor([torch.argmax(predictions[-1, :])])
predicted_ids = predicted_id

max_length = 6
for i in range(input_length, max_length):
    if predicted_id == token_to_id["<EOS>"]:
        break
    model_input = torch.cat((model_input, predicted_id))
    predictions = model(model_input)
    predicted_id = torch.tensor([torch.argmax(predictions[-1, :])])
    predicted_ids = torch.cat((predicted_ids, predicted_id))

for id in predicted_ids:
    print(id_to_token[id.item()])

Training takes only two lines. After it finishes, Josh reruns the generation code with the trained model instead of a new one.

trainer = L.Trainer(max_epochs=30)
trainer.fit(model, train_dataloaders=dataloader)

Formulas

Position encoding
$$ PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) $$

Symbols: \(pos\) is the position of the token in the input, starting at 0. \(i\) is the index of the sine and cosine pair. \(2i\) is the column for the sine value and \(2i+1\) is the column right after it, for the cosine value. \(d_{model}\) is the number of embedding values per token. What it tells you: every token gets a unique pattern of squiggle values. The "+1" only means the cosine comes after the sine; the formula inside both functions is the same.

Masked self-attention
$$ Q = XW_Q,\quad K = XW_K,\quad V = XW_V $$ $$ \text{Attention} = \text{softmax}\!\left(\frac{QK^{T}}{\sqrt{d_k}} + M\right)V $$

Symbols: \(X\) holds the word embeddings plus position encodings, one row per token. \(W_Q, W_K, W_V\) are the weight matrices in W_q, W_k, W_v. \(Q, K, V\) are the queries, keys and values, one row per token. \(QK^T\) holds the similarities (sims). \(d_k\) is the number of values in each key. \(M\) is the mask: 0 where a token may look, and \(-10^9\) (about minus infinity) where it may not. What it tells you: softmax turns the scaled similarities into percentages of influence. Those percentages then weight the values to give the attention scores.

Worked example from the video

Example

Position encoding for two tokens with \(d_{model}=4\). For the first token, \(pos=0\). With \(i=0\), \(\sin(0)=0\) and \(\cos(0)=1\). With \(i=1\), the angle is still 0, so the values are again 0 and 1. The first token gets \([0,\ 1,\ 0,\ 1]\).

For the second token, \(pos=1\) and \(i\) resets to 0. With \(i=0\) the angle is \(1/10000^{0}=1\), giving \(\sin(1)\approx0.841\) and \(\cos(1)\approx0.540\). With \(i=1\) the angle is \(1/10000^{2/4}=0.01\), giving about \(0.010\) and \(1.000\). The second token gets about \([0.841,\ 0.540,\ 0.010,\ 1.000]\).

The precomputed matrix with max_len = 3 and d_model = 2. pe starts as a 3 by 2 matrix of zeros, and position is the column \([0, 1, 2]\). With d_model = 2, embedding_index is just 0, so the divisor is 1. Column 0 gets \(\sin(0), \sin(1), \sin(2) \approx 0, 0.841, 0.909\). Column 1 gets \(\cos(0), \cos(1), \cos(2) \approx 1, 0.540, -0.416\).

The mask for four tokens. torch.ones makes a 4 by 4 matrix of ones. torch.tril keeps the lower triangle and zeros the rest. Then mask == 0 turns the zeros into True:

$$ \begin{bmatrix} F&T&T&T\\ F&F&T&T\\ F&F&F&T\\ F&F&F&F \end{bmatrix} $$

True means "ignore", so the first token sees only itself, and the last token sees all four.

Before and after training. The untrained model answers "what is statquest <EOS>" with just <EOS>. After 30 epochs it answers "awesome <EOS>". The prompt "statquest is what <EOS>" also gives "awesome <EOS>".

Common mistakes and subtle points

Watch out The forward method returns the raw output of the fully connected layer, with no softmax. nn.CrossEntropyLoss applies softmax for you during training. Adding another softmax would be wrong.
Watch out In the mask, True means "ignore this attention value". torch.tril puts ones in the lower triangle, so mask == 0 is needed to mark the upper triangle as True. masked_fill then puts \(-10^9\) there, which softmax turns into almost zero.
Watch out max_len counts the input and output tokens together. With a four-token prompt and max_len=6, only two generated tokens can be fed back in. That is why the loop runs from input_length to max_length.
Watch out Scaling by the square root of the key size has been standard since the 2017 transformer paper. Josh notes it is not required and mainly helps larger models.

If they ask you in an interview

How do you build inputs and labels to train a decoder-only transformer?
The input is the prompt, then the end-of-sequence token, then the answer. The label at each position is the next token, so the labels are the inputs shifted by one. That way the model learns from both reading the prompt and generating the answer. For "what is statquest <EOS> awesome", the labels are "is statquest <EOS> awesome <EOS>".
How is the causal mask built and applied?
I make a square matrix of ones, keep its lower triangle with torch.tril, and compare it with zero. That gives True above the diagonal, meaning "ignore". Before softmax, masked_fill replaces those scaled similarities with minus one billion. So each token gets almost zero attention from the tokens after it and cannot look ahead.
Why doesn't the model end with a softmax?
The loss is cross entropy, and PyTorch's CrossEntropyLoss already applies softmax internally. So the forward pass returns the raw fully connected outputs, one per vocabulary token. At generation time we only need argmax, and softmax would not change which token is largest.
Walk me through how the model generates a response.
I run the prompt through the model and take the output row for the last token. I pick the token with the largest value using argmax. I append it to the input and run the model again, so each prediction sees the full context. I stop when the model produces the end token or when the total length reaches max_len.
Why precompute position encodings and use register_buffer?
The sine and cosine values depend only on position and column, not on the data. So I compute them once into a max_len by d_model matrix, and adding them later is just a fast slice and add. register_buffer makes the matrix move with the model to a GPU, but it is not trained.

Recap in 30 seconds

  • The model is a decoder-only transformer, the foundation of ChatGPT, trained on two prompts that should both get the answer "awesome".
  • Tokens are mapped to IDs with token_to_id, and each label is the next token after the matching input.
  • PositionEncoding precomputes sine values in even columns and cosine values in odd columns, then adds them to the embeddings.
  • Attention uses three bias-free nn.Linear layers for Q, K and V, then scales, masks, applies softmax and multiplies by V.
  • DecoderOnlyTransformer chains embedding, position encoding, masked self-attention, a residual add and a fully connected layer.
  • Cross entropy loss includes the softmax, and Adam with a learning rate of 0.1 trains the model in 30 epochs.
  • Generation uses argmax on the last token's output, appends the result, and stops at <EOS> or at max_len.
