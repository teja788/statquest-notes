Word Embedding in PyTorch + Lightning

▶ Watch on YouTube Also in: —

This video codes a tiny word embedding network in PyTorch, first from scratch and then with nn.Linear. Lightning is a library that handles the training loop for you. Finally, Josh loads the trained embeddings into nn.Embedding for use in a bigger model.

In one breath

Josh builds a network for two sentences, "Troll 2 is great" and "Gymkata is great", that predicts the next token. First he writes every weight and every sum by hand. Then he replaces all of that with two calls to nn.Linear. After training, the two weights from each input to the hidden layer are that token's embedding. Troll 2 and Gymkata end up close together. Finally he loads those weights into nn.Embedding so they can be looked up by index or by token.

The main idea

The network has one input per unique token: Troll 2, is, great and Gymkata. Each input is one-hot encoded. That means the input for the current token gets a 1 and every other input gets a 0. The inputs connect to two hidden nodes, and those connect to four outputs, one per token.

The hidden nodes use the identity activation function. This means the output of the node is the same as its input, so it does nothing. Because only one input is 1, each hidden node simply receives the weight from that one token. So the two weights leaving a token are its two embedding values.

The outputs are not run through SoftMax inside the model. The loss, nn.CrossEntropyLoss, applies SoftMax for us and then measures how far the result is from the ideal one-hot output.

Step by step

  1. Imports. Josh imports torch, torch.nn, Adam, Uniform, TensorDataset and DataLoader, lightning as L, and pandas, matplotlib and seaborn for graphs.
  2. Training data. Each token gets a one-hot input. The label is the one-hot encoding of the token that comes next. Nothing follows "great", so Josh pretends it predicts Gymkata.
  3. Data loader. Inputs and labels go into a TensorDataset and then a DataLoader. This makes batching, shuffling and quick debugging easy when the data is large.
  4. Model from scratch. A class WordEmbeddingFromScratch inherits from LightningModule. It has __init__, forward, configure_optimizers and training_step.
  5. Look before training. Josh puts the weights into a pandas data frame and draws a seaborn scatter plot. Troll 2 and Gymkata start far apart.
  6. Train and check. A Lightning Trainer runs at most 100 epochs, or full passes through the data. Afterwards Troll 2 and Gymkata sit close together, and Troll 2 predicts "is".
  7. Same network with nn.Linear. Two calls replace all the hand-made weights and sums.
  8. Load into nn.Embedding. The trained weights are transposed and loaded with from_pretrained, ready to plug into a bigger network like a transformer.

The training data is four one-hot inputs and four one-hot labels.

inputs = torch.Tensor([[1., 0., 0., 0.],   # Troll 2
                       [0., 1., 0., 0.],   # is
                       [0., 0., 1., 0.],   # great
                       [0., 0., 0., 1.]])  # Gymkata
labels = torch.Tensor([[0., 1., 0., 0.],   # Troll 2 -> is
                       [0., 0., 1., 0.],   # is      -> great
                       [0., 0., 0., 1.],   # great   -> Gymkata
                       [0., 1., 0., 0.]])  # Gymkata -> is
dataset = TensorDataset(inputs, labels)
dataloader = DataLoader(dataset)

The from-scratch model makes every weight with nn.Parameter, starting from a uniform draw between -0.5 and 0.5. Josh picks this range to match what nn.Linear will do later.

class WordEmbeddingFromScratch(L.LightningModule):
    def __init__(self):
        super().__init__()
        min_value, max_value = -0.5, 0.5
        self.input1_w1 = nn.Parameter(Uniform(min_value, max_value).sample())  # Troll 2 -> top
        self.input1_w2 = nn.Parameter(Uniform(min_value, max_value).sample())  # Troll 2 -> bottom
        # ... the same for input2 to input4, then output1_w1 ... output4_w2
        self.loss = nn.CrossEntropyLoss()

    def forward(self, input):
        input = input[0]                         # remove the extra brackets
        inputs_to_top_hidden = (input[0] * self.input1_w1 + input[1] * self.input2_w1 +
                                input[2] * self.input3_w1 + input[3] * self.input4_w1)
        inputs_to_bottom_hidden = (input[0] * self.input1_w2 + input[1] * self.input2_w2 +
                                   input[2] * self.input3_w2 + input[3] * self.input4_w2)
        output1 = (inputs_to_top_hidden * self.output1_w1 +
                   inputs_to_bottom_hidden * self.output1_w2)
        # ... output2 to output4 the same way
        output_presoftmax = torch.stack([output1, output2, output3, output4])
        return output_presoftmax

    def configure_optimizers(self):
        return Adam(self.parameters(), lr=0.1)

    def training_step(self, batch, batch_idx):
        input_i, label_i = batch
        output_i = self.forward(input_i)
        loss = self.loss(output_i, label_i[0])
        return loss

The weights are read out with .item() into a data frame, plotted, and then the model is trained.

model_from_scratch = WordEmbeddingFromScratch()
data = {"w1": [model_from_scratch.input1_w1.item(), ...],   # weights to top node
        "w2": [model_from_scratch.input1_w2.item(), ...],   # weights to bottom node
        "token": ["Troll2", "is", "great", "Gymkata"],
        "input": ["input1", "input2", "input3", "input4"]}
df = pd.DataFrame(data)
sns.scatterplot(data=df, x="w1", y="w2")
plt.text(df.w1[0], df.w2[0], df.token[0], horizontalalignment="left",

trainer = L.Trainer(max_epochs=100)
trainer.fit(model_from_scratch, train_dataloaders=dataloader)

The nn.Linear version needs far less code. There is no bias, and the input no longer needs its extra brackets removed.

class WordEmbeddingWithLinear(L.LightningModule):
    def __init__(self):
        super().__init__()
        self.input_to_hidden = nn.Linear(in_features=4, out_features=2, bias=False)
        self.hidden_to_output = nn.Linear(in_features=2, out_features=4, bias=False)
        self.loss = nn.CrossEntropyLoss()

    def forward(self, input):
        hidden = self.input_to_hidden(input)
        output_values = self.hidden_to_output(hidden)
        return output_values
    # configure_optimizers and training_step are similar to before

model_linear = WordEmbeddingWithLinear()
data = {"w1": model_linear.input_to_hidden.weight.detach()[0].numpy(),
        "w2": model_linear.input_to_hidden.weight.detach()[1].numpy(), ...}

Finally, the trained weights are loaded into nn.Embedding. A dictionary lets you look up a token by name instead of by index.

word_embeddings = nn.Embedding.from_pretrained(model_linear.input_to_hidden.weight.T)
print(word_embeddings.weight)               # now 4 rows, 2 columns
print(word_embeddings(torch.tensor(0)))     # Troll 2's embedding

vocab = {"Troll2": 0, "is": 1, "great": 2, "Gymkata": 3}
print(word_embeddings(torch.tensor(vocab["Troll2"])))

Formulas

Hidden node sums
$$ h_{\text{top}} = \sum_{i=1}^{4} x_i\, w_{1,i} \qquad h_{\text{bottom}} = \sum_{i=1}^{4} x_i\, w_{2,i} $$

Symbols: \(x_i\) is input \(i\) of the one-hot encoding (1 for the current token, 0 otherwise). \(w_{1,i}\) is the weight from input \(i\) to the top hidden node, and \(w_{2,i}\) the weight to the bottom node. \(h\) is the hidden value; the identity activation leaves it unchanged. What it tells you: with a one-hot input, \(h_{\text{top}}\) and \(h_{\text{bottom}}\) are just that token's two weights, which is why they are its embedding.

Output sums (before SoftMax)
$$ o_j = h_{\text{top}}\, v_{j,1} + h_{\text{bottom}}\, v_{j,2} $$

Symbols: \(o_j\) is the raw value for output token \(j\). \(v_{j,1}\) and \(v_{j,2}\) are the weights from the top and bottom hidden nodes to output \(j\). What it tells you: this is all forward computes; the four \(o_j\) are stacked and returned without SoftMax.

SoftMax (done inside the loss)
$$ p_j = \frac{e^{o_j}}{\sum_{k=1}^{4} e^{o_k}} $$

Symbols: \(p_j\) is the predicted probability for token \(j\); \(e\) is Euler's number; the sum runs over all four outputs. What it tells you: nn.CrossEntropyLoss turns the raw outputs into probabilities like this, then compares them with the one-hot label.

Worked example from the video

Example

The two sentences give four training pairs: Troll 2 → is, is → great, great → Gymkata (a stand-in, since nothing follows "great"), and Gymkata → is. Troll 2 and Gymkata both predict "is", so they are used in the same context.

Before training, Josh's first weights for Troll 2 were randomly set to 0.38 and 0.42. Run Troll 2 as \([1, 0, 0, 0]\): \(h_{\text{top}} = 1 \times 0.38 + 0 + 0 + 0 = 0.38\) and \(h_{\text{bottom}} = 1 \times 0.42 = 0.42\). So Troll 2 sits at the point (0.38, 0.42) on the W1 vs W2 plot. In the starting plot, Troll 2 and Gymkata are far apart.

After 100 epochs with Adam and a learning rate of 0.1, the plot shows Troll 2 and Gymkata very close together. Josh then passes \([1, 0, 0, 0]\) into the model, applies nn.Softmax(dim=0), and rounds to two decimals. The result is \([0, 1, 0, 0]\), the one-hot encoding for "is", which is correct. The other inputs also give their correct outputs.

Common mistakes and subtle points

Watch out In the from-scratch forward, return the outputs with torch.stack. If you just wrap them in square brackets as a plain list, the gradients get stripped off and backpropagation cannot work.
Watch out Do not add SoftMax inside forward. nn.CrossEntropyLoss already applies it. You only add nn.Softmax(dim=0) yourself when checking predictions; dim=1 would apply it to columns instead of rows.
Watch out nn.Linear stores the input weights in rows, one per hidden node. nn.Embedding expects them in columns, one row per token, so use .T when calling from_pretrained.
Watch out The from-scratch forward receives the input wrapped in an extra set of brackets, so it starts with input = input[0]. With nn.Linear this step is not needed. When reading nn.Linear weights into pandas, call .detach() before .numpy().

If they ask you in an interview

Where exactly are the word embeddings in this network?
They are the weights from the inputs to the hidden layer. Because the input is one-hot and the hidden activation is the identity, each hidden node just receives one weight from the active token. So each token's embedding is its set of weights to the hidden nodes, here two numbers.
Why is there no SoftMax in the forward method?
The loss is nn.CrossEntropyLoss, which applies SoftMax to the raw outputs and then compares them with the ideal one-hot label. Adding SoftMax in the model would apply it twice. When I want actual predictions after training, I apply SoftMax myself.
How does nn.Linear replace the hand-built version?
One nn.Linear(4, 2, bias=False) holds the eight input-to-hidden weights and does the multiply-and-add. A second nn.Linear(2, 4, bias=False) holds the hidden-to-output weights. The identity activation can be skipped, so forward is just two calls. The model is the same, with much less code.
How would you reuse trained or pre-trained embeddings?
I load them into nn.Embedding.from_pretrained, transposing the nn.Linear weights so each token is a row. Then I look embeddings up by index, or by token through a small dictionary. The same idea works for larger sets, like Word2Vec or embeddings from a transformer, and the object can feed a bigger network.
