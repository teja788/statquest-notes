Introduction to Coding Neural Networks with PyTorch and Lightning

▶ Watch on YouTube Also in: Neural Networks / Deep Learning (video 30)

Josh rebuilds the small drug dosage neural network from the PyTorch introduction, this time with Lightning. Lightning finds a good learning rate and writes the training loop for you. It also lets the same code run on a laptop or on GPUs.

In one breath

The network class now inherits from LightningModule instead of nn.Module. All the code about the network lives in one class: __init__, forward, configure_optimizers and training_step. The training data is wrapped in a DataLoader. A Lightning Trainer finds a learning rate with lr_find and then trains the model with fit. The final bias goes from 0 to about −16.0098, and the network fits the three data points again.

The main idea

With plain PyTorch, Josh wrote a class for the weights, biases and forward pass. Then, completely separate from that class, he wrote a long loop to train it. He also had to pick the learning rate, the step size for gradient descent, by hand. Picking a good learning rate is not always easy.

Moving the code to GPUs or TPUs would also mean many code changes. Lightning fixes all three problems. You put everything about the network into one class. You hand that class to a Trainer, which runs the training loop for you. The only part of the loop you still write is the loss.

Step by step

First come the imports. Everything is as before, plus Lightning and the data helpers.

import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.optim import SGD
import lightning as L
from torch.utils.data import TensorDataset, DataLoader
  1. Build the pre-trained network. The class is called BasicLightning and inherits from LightningModule. The __init__ method calls the parent's __init__, then makes each weight and bias an nn.Parameter holding a tensor.
  2. Write forward. The input goes through a top and a bottom ReLU, and each ReLU output is scaled by a weight. The two scaled values are added to the final bias, and the sum goes through a final ReLU.
  3. Test it. Josh makes doses between 0 and 1 with torch.linspace and passes them to model = BasicLightning(). Calling the model runs forward by default. A Seaborn line plot shows the expected bent shape.
  4. Make a version to train. He copies the class as BasicLightningTrain and sets the final bias to 0.0 with requires_grad=True. He also adds self.learning_rate = 0.01, which is only a placeholder.
  5. Wrap the data. The inputs and labels go into a TensorDataset, and that goes into a DataLoader.
  6. Add two methods. configure_optimizers returns SGD, short for stochastic gradient descent, using the learning rate variable. training_step takes a batch and its index and returns the loss.
  7. Find a learning rate, then train. A Trainer runs lr_find, the model gets the suggested rate, and then trainer.fit trains it.
  8. Check and plot. Josh prints the new final bias and graphs the trained model. This time he reuses the trained model instead of making a new one.

Here is the trainable class. Only final_bias is trained; the other weights and biases keep requires_grad=False.

class BasicLightningTrain(L.LightningModule):
    def __init__(self):
        super().__init__()
        self.w00 = nn.Parameter(torch.tensor(1.7), requires_grad=False)
        self.b00 = nn.Parameter(torch.tensor(-0.85), requires_grad=False)
        self.w01 = nn.Parameter(torch.tensor(-40.8), requires_grad=False)
        self.w10 = nn.Parameter(torch.tensor(12.6), requires_grad=False)
        self.b10 = nn.Parameter(torch.tensor(0.0), requires_grad=False)
        self.w11 = nn.Parameter(torch.tensor(2.7), requires_grad=False)
        self.final_bias = nn.Parameter(torch.tensor(0.0), requires_grad=True)
        self.learning_rate = 0.01  # placeholder

    def forward(self, input):
        input_to_top_relu = input * self.w00 + self.b00
        scaled_top_relu_output = F.relu(input_to_top_relu) * self.w01
        input_to_bottom_relu = input * self.w10 + self.b10
        scaled_bottom_relu_output = F.relu(input_to_bottom_relu) * self.w11
        input_to_final_relu = scaled_top_relu_output + scaled_bottom_relu_output + self.final_bias
        return F.relu(input_to_final_relu)

    def configure_optimizers(self):
        return SGD(self.parameters(), lr=self.learning_rate)

    def training_step(self, batch, batch_idx):
        input_i, label_i = batch
        output_i = self.forward(input_i)
        loss = (output_i - label_i)**2
        return loss

The training data goes into a DataLoader.

inputs = torch.tensor([0., 0.5, 1.])
labels = torch.tensor([0., 1., 0.])
dataset = TensorDataset(inputs, labels)
dataloader = DataLoader(dataset)

Then the Trainer finds a learning rate and fits the model.

model = BasicLightningTrain()
trainer = L.Trainer(max_epochs=34)
tuner = L.pytorch.tuner.Tuner(trainer)
lr_find_results = tuner.lr_find(model, train_dataloaders=dataloader,
                                min_lr=0.001, max_lr=1.0,
                                early_stop_threshold=None)
new_lr = lr_find_results.suggestion()
model.learning_rate = new_lr

trainer.fit(model, train_dataloaders=dataloader)
print(model.final_bias.data)

Why a DataLoader? Josh gives three reasons. It makes it easy to access the data in batches, which helps when the data is bigger than memory. It makes it easy to shuffle the data each epoch. And it makes it easy to use a small fraction of the data for a quick training run while debugging.

GPUs. A laptop may have one CPU, the central processing unit, with only a few computing cores. With one CPU, the weight tensors and the data tensors all sit in the same place. A GPU, or graphics processing unit, can have 10 or even 100 times more cores, so training is much faster. In plain PyTorch you must move tensors to the GPUs yourself, and keeping track of them gets complicated. With Lightning you set accelerator="auto" and devices="auto" when you create the Trainer. Lightning then detects whether GPUs are available and how many there are. The same code runs on your laptop and on a machine with many GPUs.

trainer = L.Trainer(max_epochs=34, accelerator="auto", devices="auto")

Formulas

Forward pass
$$ \text{output} = \text{ReLU}\Big( w_{01}\,\text{ReLU}(w_{00}x + b_{00}) + w_{11}\,\text{ReLU}(w_{10}x + b_{10}) + b_{\text{final}} \Big) $$

Symbols: \(x\) is the drug dose. \(w_{00}, b_{00}\) are the weight and bias into the top ReLU, and \(w_{01}\) scales its output. \(w_{10}, b_{10}\) and \(w_{11}\) do the same for the bottom ReLU. \(b_{\text{final}}\) is the final bias, the only value being trained. \(\text{ReLU}(z)\) means \(\max(0, z)\). What it tells you: this is exactly what the forward method computes.

Loss (sum of squared residuals)
$$ \text{SSR} = \sum_{i=1}^{3} \big(\text{output}_i - \text{label}_i\big)^2 $$

Symbols: \(i\) indexes the three training points. \(\text{output}_i\) is the network's prediction for dose \(i\). \(\text{label}_i\) is the known effectiveness. What it tells you: Josh calls this loss the sum of the squared residuals. Here each batch holds one point, so training_step returns one squared residual at a time.

Worked example from the video

Example

Data. The doses are 0, 0.5 and 1. The known effectiveness values are 0, 1 and 0.

Before training. With the final bias set to 0, the graph shows effectiveness of 17 at dose 0.5. At that dose the top ReLU gets \(1.7 \times 0.5 - 0.85 = 0\), so it adds nothing. The bottom path gives \(\text{ReLU}(12.6 \times 0.5) \times 2.7 = 6.3 \times 2.7 \approx 17\). That is far above the target of 1, so the final bias must be optimized.

Learning rate. lr_find tries 100 candidate learning rates between 0.001 and 1. With early_stop_threshold=None it tests all of them. The suggested rate is 0.00214.

Training. An epoch is one pass through all three training points. With max_epochs=34, trainer.fit moves the final bias to −16.0098. At dose 0.5 the output is now about \(17 - 16.0098 \approx 1\), which matches the label. The final graph shows the network fits the data again.

Common mistakes and subtle points

Watch out Once the final bias has a gradient, the output tensor carries gradient information too. Josh calls .detach() on the output values before plotting, to get a new tensor that holds only the values.
Watch out After you add new methods to the class, make a new model from it. For the final graph, do the opposite: reuse the trained model, or you lose the optimized bias.
Watch out The 0.01 learning rate in __init__ is only a placeholder. configure_optimizers must read self.learning_rate, so the rate found by lr_find is the one SGD actually uses.
Watch out 34 epochs is enough here because it worked before. If it were not, you would not start over. Lightning lets you add more epochs right where training left off.

If they ask you in an interview

What does Lightning add on top of plain PyTorch?
It puts all the code about the network in one class and writes the training loop for you. The Trainer calls zero_grad, backward and step, so you only write the loss. It can also suggest a learning rate, and it runs the same code on CPUs or GPUs.
Which methods does a LightningModule need for training, and what does each do?
__init__ creates the weights, biases and the learning rate. forward runs data through the network. configure_optimizers returns the optimizer, here SGD with the learning rate variable. training_step takes a batch and its index and returns the loss.
What happens when you call trainer.fit?
The Trainer first calls configure_optimizers to set up the optimizer. Then it calls training_step to get the loss. After that it calls zero_grad, backward and step, and it repeats this for each epoch you asked for.
How does Lightning help you choose a learning rate?
You call lr_find on a tuner with the model, the data and a minimum and maximum rate. By default it builds 100 candidate rates in that range. Calling suggestion on the results gives an improved rate, which you then set on the model before training.
Why use a DataLoader, even for tiny data?
Lightning expects the training data wrapped in a DataLoader. It also pays off with big data. It gives easy batches when data does not fit in memory, easy shuffling each epoch, and easy use of a small slice for quick debugging.

Recap in 30 seconds

  • Inherit from LightningModule instead of nn.Module; running a pre-trained network works the same as before.
  • Put __init__, forward, configure_optimizers and training_step together in one class.
  • Wrap the training data in a TensorDataset and then a DataLoader.
  • Use the Trainer's tuner and lr_find to get a learning rate; here it suggested 0.00214.
  • Call trainer.fit(model, dataloader), and the Trainer runs the full training loop for you.
  • In the example, the final bias moved from 0 to −16.0098, and the network fits the three doses again.
  • Setting accelerator="auto" and devices="auto" lets the same code run on a laptop CPU or on many GPUs.
