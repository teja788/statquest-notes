Random Forests in R

▶ Watch on YouTube

Josh builds a random forest in R on the UCI heart disease data. He cleans the data, fills the gaps, checks the error, tunes two settings, and clusters the patients.

In one breath

Most of the work is cleaning: question marks become NA, and coded columns become factors. rfImpute fills the missing values, and randomForest builds the model. Printing the model shows that 83.5% of the out-of-bag samples are classified correctly. Josh then checks the number of trees and the number of variables per split. Last, he turns the proximity matrix into an MDS plot of the patients.

The main idea

A random forest is many decision trees, each built on a bootstrap sample of the rows. The theory is in the two earlier videos. The key habit here is that the forest grades itself. Rows left out of a tree's bootstrap sample are called out-of-bag, and only those trees predict them. The share of these predictions that are wrong is the out-of-bag error.

One model object holds everything Josh needs afterwards. It has the confusion matrix, the error rate after every tree, and, if you ask, the proximity matrix.

Step by step

  1. Load the libraries, read the data, and name the columns.
  2. Turn question marks into NA and coded columns into factors.
  3. Set the seed and fill the missing values with rfImpute.
  4. Build the forest, then print it to see the error and the confusion matrix.
  5. Plot the error against the number of trees, and loop over mtry.
  6. Draw an MDS plot from the proximity matrix.

2. Clean the columns

The str function shows the structure of the data. Sex and chest pain are stored as numbers but should be factors, which are category columns. The ca and thal columns use a question mark for a missing value.

data[data == "?"] <- NA

data[data$sex == 0,]$sex <- "F"          # easier on the eyes
data[data$sex == 1,]$sex <- "M"
data$sex <- as.factor(data$sex)

data$cp <- as.factor(data$cp)            # and fbs, restecg, exang, slope
data$ca <- as.factor(as.integer(data$ca))    # the "?" made it a string
data$thal <- as.factor(as.integer(data$thal))

data$hd <- as.factor(ifelse(test=data$hd == 0, yes="Healthy", no="Unhealthy"))

The same idea in Python. Read the file with pandas and mark the question marks as missing.

import pandas as pd
cols = ["age","sex","cp","trestbps","chol","fbs","restecg",
        "thalach","exang","oldpeak","slope","ca","thal","hd"]
df = pd.read_csv(url, header=None, names=cols, na_values="?")
df["hd"] = (df["hd"] > 0).map({True: "Unhealthy", False: "Healthy"})

cat = ["sex","cp","fbs","restecg","exang","slope","ca","thal"]
X, y = df.drop(columns="hd"), df["hd"]

3. Fill the missing values, then build the forest

rfImpute builds forests to guess the missing values. The formula hd ~ . means "predict heart disease from all other columns". The iter argument sets how many forests to build, and four to six is usually enough. After each pass it prints the out-of-bag error.

set.seed(42)
data.imputed <- rfImpute(hd ~ ., data=data, iter=6)

model <- randomForest(hd ~ ., data=data.imputed, proximity=TRUE)
model

The same idea in Python. Scikit-learn has no rfImpute, so use IterativeImputer, a different method with the same goal. Impute first, then one-hot encode the coded columns, because scikit-learn cannot split on a category directly. Fit with oob_score=True so the forest grades itself.

from sklearn.experimental import enable_iterative_imputer  # noqa
from sklearn.impute import IterativeImputer
from sklearn.ensemble import RandomForestClassifier

X = pd.DataFrame(IterativeImputer(max_iter=6, random_state=42)
                 .fit_transform(X), columns=X.columns)
X[cat] = X[cat].round()                  # imputed codes back to whole numbers
X = pd.get_dummies(X, columns=cat)       # one-hot encode after imputing

rf = RandomForestClassifier(n_estimators=500, max_features="sqrt",
                            oob_score=True, random_state=42).fit(X, y)
print("OOB error:", round(1 - rf.oob_score_, 3))

4. Read the printed summary

The type is classification, because the forest classifies samples. Predicting weight would say regression. Leaving out the target would say unsupervised. The forest has 500 trees and tries 3 variables at each internal node; both are defaults. Last come the out-of-bag error and the confusion matrix.

5. Are 500 trees enough?

The model holds a matrix called err.rate. Its columns are the overall out-of-bag error, the healthy error, and the unhealthy error. Row 1 is the rate after one tree, and the last row is after all 500. Josh reshapes it so ggplot2 can draw one line per error type.

oob.error.data <- data.frame(
  Trees = rep(1:nrow(model$err.rate), times=3),
  Type  = rep(c("OOB","Healthy","Unhealthy"), each=nrow(model$err.rate)),
  Error = c(model$err.rate[,"OOB"],
            model$err.rate[,"Healthy"],
            model$err.rate[,"Unhealthy"]))

ggplot(data=oob.error.data, aes(x=Trees, y=Error)) + geom_line(aes(color=Type))

model <- randomForest(hd ~ ., data=data.imputed, ntree=1000, proximity=TRUE)

The same idea in Python. Scikit-learn keeps no error history. So grow the forest with warm_start=True and record the error after each new tree.

import numpy as np, matplotlib.pyplot as plt

rf = RandomForestClassifier(n_estimators=1, max_features="sqrt",
                            oob_score=True, warm_start=True, random_state=42)
oob_err = []
for n in range(1, 1001):
    rf.set_params(n_estimators=n).fit(X, y)   # warnings are normal at first
    oob_err.append(1 - rf.oob_score_)

plt.plot(range(1, 1001), oob_err)
plt.xlabel("Number of trees"); plt.ylabel("OOB error rate")

6. How many variables at each node?

The other setting is mtry, the number of variables tried at each split. A loop builds one forest for each value from 1 to 10. It stores the out-of-bag error after all 1000 trees. The lowest error came at mtry = 3, the default.

oob.values <- vector(length=10)
for(i in 1:10) {
  temp.model <- randomForest(hd ~ ., data=data.imputed, mtry=i, ntree=1000)
  oob.values[i] <- temp.model$err.rate[nrow(temp.model$err.rate), 1]
}
oob.values

The same idea in Python. The max_features argument is mtry under another name.

for m in range(1, 11):
    fit = RandomForestClassifier(n_estimators=1000, max_features=m,
                                 oob_score=True, random_state=42).fit(X, y)
    print(m, round(1 - fit.oob_score_, 4))

7. Cluster the patients with an MDS plot

The proximity of two patients is how often they land in the same leaf. One minus proximity is a distance. cmdscale runs classical multidimensional scaling (MDS), which draws the patients on a flat map. The eigenvalues give the share of variation each axis explains.

distance.matrix <- dist(1 - model$proximity)
mds.stuff <- cmdscale(distance.matrix, eig=TRUE, x.ret=TRUE)
mds.var.per <- round(mds.stuff$eig / sum(mds.stuff$eig) * 100, 1)

mds.data <- data.frame(Sample=rownames(mds.stuff$points),
                       X=mds.stuff$points[,1], Y=mds.stuff$points[,2],
                       Status=data.imputed$hd)

ggplot(data=mds.data, aes(x=X, y=Y, label=Sample)) +
  geom_text(aes(color=Status)) +
  xlab(paste("MDS1 - ", mds.var.per[1], "%", sep="")) +
  ylab(paste("MDS2 - ", mds.var.per[2], "%", sep=""))

The same idea in Python. Scikit-learn does not return proximities. So build them from the leaf each sample falls into.

from sklearn.manifold import MDS

leaves = rf.apply(X)                                   # samples x trees
prox = (leaves[:, None, :] == leaves[None, :, :]).mean(axis=2)
coords = MDS(n_components=2, dissimilarity="precomputed",
             random_state=42).fit_transform(1 - prox)

plt.scatter(coords[:, 0], coords[:, 1], c=(y == "Unhealthy"))

Formulas

Out-of-bag error rate
$$ \text{OOB error} = \frac{1}{N}\sum_{i=1}^{N} \mathbf{1}\!\left(\hat{y}^{\,\text{oob}}_i \neq y_i\right) $$

Symbols: \(N\) is the number of patients. \(y_i\) is the true label. \(\hat{y}^{\,\text{oob}}_i\) is the vote of only the trees that did not see patient \(i\). \(\mathbf{1}(\cdot)\) is 1 for a wrong label and 0 for a right one. What it tells you: it is an honest error from unseen data, so no separate test set is needed.

Default number of variables per node
$$ m_{\text{try}} = \left\lfloor \sqrt{p} \right\rfloor \ \text{(classification)}, \qquad m_{\text{try}} = \left\lfloor p/3 \right\rfloor \ \text{(regression)} $$

Symbols: \(p\) is the number of predictor columns. \(m_{\text{try}}\) is how many of them a tree may choose from at each node. \(\lfloor\cdot\rfloor\) rounds down. What it tells you: with 13 predictors the default is 3, as the summary shows. It is a starting point, not a proven best.

Proximity turned into distance
$$ d_{ij} = 1 - \text{prox}_{ij}, \qquad \text{prox}_{ij} = \frac{\text{trees where } i \text{ and } j \text{ share a leaf}}{\text{total number of trees}} $$

Symbols: \(\text{prox}_{ij}\) runs from 0 to 1 and says how alike patients \(i\) and \(j\) look to the forest. \(d_{ij}\) is their distance. What it tells you: two patients who always share a leaf get a distance of 0.

Variation explained by an MDS axis
$$ \text{percent}_k = \frac{\lambda_k}{\sum_j \lambda_j} \times 100 $$

Symbols: \(\lambda_k\) is the \(k\)-th eigenvalue from cmdscale. The sum runs over all eigenvalues. What it tells you: here the x-axis carries 47% and the y-axis 14%, so the big differences run left to right.

Worked example from the video

Example

Printing the model gives this confusion matrix for the 303 patients. Each row is the true label, and each column is the forest's call.

Called HealthyCalled UnhealthyClass error
Healthy1412323 / 164 = 14.0%
Unhealthy2711227 / 139 = 19.4%

The overall out-of-bag error uses both kinds of mistake:

$$ \text{OOB error} = \frac{23 + 27}{303} = \frac{50}{303} = 0.165 $$

So 83.5% of the out-of-bag samples were classified correctly. A forest with 1000 trees gave the same error rate.

Common mistakes and subtle points

Watch out

Do not skip the factor conversions. Chest pain uses the codes 1 to 4, and these codes are names, not amounts. Left as numbers, the trees would treat 4 as larger than 1.

Watch out

The error that rfImpute prints should fall if the guesses improve. Here it does not, even with 20 iterations. That means the guesses are as good as this method can make them.

Watch out

The defaults of 500 trees and mtry = 3 were right here, but only testing showed it. You cannot know the curve is flat until you grow more trees than you keep.

If they ask you in an interview

What is the out-of-bag error and why can it replace a test set?
Each tree trains on a bootstrap sample, so some rows are left out of it. Each row is predicted only by the trees that never saw it. The share of wrong predictions is the out-of-bag error. Because the data are unseen, the estimate is honest without a test set.
How do you choose the number of trees and the number of variables per split?
I plot the out-of-bag error against the number of trees and stop where it flattens. Here it settled just after 500 trees. For variables per split, I loop over a small range and compare the final errors. The default of 3 won here, but I would not assume it.
What is the proximity matrix and what can you do with it?
Proximity is the share of trees in which two samples end in the same leaf. One minus proximity is a distance, which feeds an MDS plot. Here the plot split healthy from unhealthy patients. It also flagged patient 253, who may have been misdiagnosed.
How does a random forest deal with missing values?
In R I call rfImpute, which refines its guesses with forests and proximities. Four to six passes are usually enough. I watch the printed out-of-bag error to see if the guesses still improve. In scikit-learn I would use an iterative imputer instead.
