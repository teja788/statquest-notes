XGBoost Part 4 (of 4): Crazy Cool Optimizations

▶ Watch on YouTube Also in: —

Parts 1 to 3 showed how XGBoost builds its trees. This video covers the other parts, the optimizations that make XGBoost fast on large training data.

In one breath

For huge data, XGBoost tests only quantiles as split thresholds, not every value. It finds these quantiles with a weighted quantile sketch that can run on many computers in parallel. Each observation's weight is the Hessian, so uncertain predictions get smaller quantiles. Sparsity-aware split finding learns a default path for missing values. Cache-aware access and blocks for out-of-core computation make good use of the computer hardware.

The main idea

XGBoost builds trees with a greedy algorithm. That means it picks the threshold with the largest gain now, without looking ahead to see how later splits play out. This is fast, but with a lot of measurements it still has to test every possible threshold. With many variables, that takes forever.

The approximate greedy algorithm fixes this. It divides the data into quantiles and tests only the quantile boundaries as candidate thresholds. More quantiles give better predictions but take longer. By default XGBoost uses about 33 quantiles.

These are weighted quantiles. In a normal quantile, each bin has the same number of observations. In a weighted quantile, each bin has the same sum of weights. The weight of an observation is the Hessian, the second derivative of the loss function. This is the same quantity behind the cover metric from Parts 2 and 3.

Step by step

  1. Greedy recap. XGBoost starts at 0.5, computes residuals, and picks the threshold with the largest gain. It does not look ahead, so it builds trees quickly.
  2. Approximate greedy. With lots of data, XGBoost tests only quantile boundaries as thresholds. One quantile is fast but predicts badly. More quantiles predict better but slow down tree building.
  3. Parallel learning and the quantile sketch. When data does not fit in memory, even sorting and finding quantiles is slow. XGBoost splits the data across computers on a network. A sketch is a fast algorithm that gives an approximate answer. The quantile sketch combines the pieces into an approximate histogram, which gives approximate quantiles. This is why the default is "about" 33 quantiles.
  4. Weighted quantiles. Each bin holds a similar sum of weights. For regression all weights are 1, so these are ordinary quantiles. For classification the weight is \(p(1-p)\), so low-confidence points land in smaller bins.
  5. Only for huge data. XGBoost uses approximate greedy, parallel learning and the weighted quantile sketch only when the training data is huge. For small data it uses the normal greedy algorithm.
  6. Sparsity-aware split finding. Put rows with a missing value in a separate table. For each threshold on the known rows, compute the gain twice: missing rows in the left leaf, then in the right leaf. Pick the best overall. That direction becomes the default path for missing values.
  7. Cache-aware access. The CPU cache is the fastest memory, then main memory, then the hard drive. XGBoost keeps the gradients and Hessians in the cache, so it can quickly compute similarity scores and output values.
  8. Blocks for out-of-core computation. When data must sit on the hard drive, XGBoost compresses it. Decompressing on the CPU is faster than reading more from disk. With several drives, it uses sharding: each drive gets a unique set of rows, so drives read at the same time.
  9. Random subsets. XGBoost can also build each tree from a random subset of the data. It can look at only a random subset of features when it decides how to split.

Formulas

Weight of an observation
$$ w_i = \text{Hessian}_i = \begin{cases} 1 & \text{regression} \\ p_i\,(1-p_i) & \text{classification} \end{cases} $$

Symbols: \(w_i\) is the weight of observation \(i\) in the weighted quantile sketch. The Hessian is the second derivative of the loss function. \(p_i\) is the previously predicted probability for observation \(i\). What it tells you: in classification the weight is largest near \(p = 0.5\) and small near 0 or 1, so weight measures how unsure the model is.

Weighted quantile rule
$$ \sum_{i \in Q_1} w_i \;\approx\; \sum_{i \in Q_2} w_i \;\approx\; \cdots \;\approx\; \sum_{i \in Q_K} w_i $$

Symbols: \(Q_1, \dots, Q_K\) are the quantiles (bins). \(w_i\) is the weight of each observation inside a bin. What it tells you: bins hold a similar total weight, not a similar count, so heavy (uncertain) points get bins with fewer observations.

Sparsity-aware choice
$$ \text{best split} = \max_{t}\; \max\big(\text{Gain}_{\text{left}}(t),\ \text{Gain}_{\text{right}}(t)\big) $$

Symbols: \(t\) is a candidate threshold, such as the average of two neighbouring sorted dosages. \(\text{Gain}_{\text{left}}(t)\) is the gain when all rows with a missing value go to the left leaf. \(\text{Gain}_{\text{right}}(t)\) is the gain when they go to the right leaf. What it tells you: the model picks a threshold and a side for missing values at the same time.

Worked example from the video

Example

Josh uses dosage to predict whether a drug is effective. After some trees, six observations have these previously predicted probabilities: two at 0.1, two at 0.9, one at 0.6 and one at 0.4.

Weights: \(0.1 \times (1-0.1) = 0.09\), and \(0.9 \times (1-0.9) = 0.09\). For the uncertain points, \(0.6 \times 0.4 = 0.24\) and \(0.4 \times 0.6 = 0.24\).

Equal quantiles of two observations each would lump the last two points together. They then end up in the same leaf. Their positive and negative residuals cancel, so the predictions hardly improve.

Weighted quantiles give bin sums of 0.18, 0.18, 0.24 and 0.24. The two low-confidence points now sit in separate bins.

For missing data, Josh tests thresholds 7.5, 15.5 and 23 on the rows with known dosages. Each gets a Gain left and a Gain right. The largest was Gain left at Dosage < 15.5. So a new row without a dosage goes to the left leaf.

Common mistakes and subtle points

Watch out The approximate greedy algorithm, parallel learning and the weighted quantile sketch are only used for huge training data. On small data, XGBoost uses the normal greedy algorithm and tests every threshold.
Watch out For regression every weight is 1, so weighted quantiles are just normal quantiles. The weighting only changes things in classification. There, the weights are recalculated after each tree.
Watch out "About 33 quantiles" is not exact because the sketch gives approximate quantiles from an approximate histogram.
Watch out Cache-aware access and blocks for out-of-core computation are about hardware, not statistics. Josh uses them to argue that machine learning is more than applied statistics.

If they ask you in an interview

How does XGBoost handle missing values?
It uses sparsity-aware split finding. For each threshold, it computes the gain with all missing rows in the left leaf, and again with them in the right leaf. The best combination wins. That side becomes the default path for new rows with a missing value.
What is the approximate greedy algorithm?
Instead of testing every possible threshold, XGBoost tests only quantile boundaries. By default it uses about 33 quantiles. More quantiles give better splits but take longer. It is only used for very large data sets.
Why weighted quantiles, and what are the weights?
Each weight is the Hessian, the second derivative of the loss. For classification that is p times one minus p, which is largest when the model is unsure. Bins with equal total weight put uncertain points in smaller bins. So the tree can separate them instead of letting their residuals cancel.
Which XGBoost optimizations are about hardware?
Cache-aware access keeps gradients and Hessians in the CPU cache, so similarity scores are fast. Out-of-core blocks compress data on disk, because decompressing is faster than reading from disk. Sharding spreads rows across drives so they can read in parallel.

Recap in 30 seconds

  • XGBoost is greedy: it picks the best split now without looking ahead.
  • For huge data, it tests only about 33 quantiles instead of every threshold.
  • A quantile sketch builds approximate quantiles from data spread across many computers.
  • Weighted quantiles use the Hessian as weight, which is 1 for regression and p(1 − p) for classification.
  • Sparsity-aware split finding tries missing values in both leaves and keeps the better side as a default path.
  • Cache-aware access, compression and sharding make good use of the hardware.
  • Random subsets of rows and features can speed up tree building further.
