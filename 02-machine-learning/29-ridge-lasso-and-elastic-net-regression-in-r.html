Ridge, Lasso and Elastic-Net Regression in R

▶ Watch on YouTube

This video shows how to run ridge, lasso and elastic-net regression in R with the glmnet library. It also shows how to pick the best mix of the two penalties by testing many values and comparing the test error.

In one breath

The glmnet package does not use two lambdas. It uses one lambda for the size of the penalty and one alpha for the mix of lasso and ridge. Josh builds a fake data set with 1,000 samples and 5,000 parameters, where only 15 parameters really matter. He fits ridge, lasso and elastic net with cross-validation, then compares the mean squared error on held-out data. Lasso wins clearly, because most of the 5,000 parameters are pure noise and lasso can remove them.

The main idea

The name glmnet has two halves. The GLM part means generalized linear models, so the same tool works for linear regression, logistic regression and a few others. The net part comes from elastic net.

In the earlier video on elastic net, the lasso penalty and the ridge penalty each had their own lambda. The glmnet package does it differently. There is a single lambda, plus a parameter called alpha that runs from 0 to 1.

Alpha sets the mix. When alpha is 0, the lasso part disappears and you are left with plain ridge regression. When alpha is 1, the ridge part disappears and you are left with plain lasso regression. When alpha sits between 0 and 1, you get both penalties, which shrinks correlated variables better than either one alone.

Lambda sets how strong the whole penalty is. When lambda is 0, the penalty is gone and you are back to ordinary least squares, or to maximum likelihood for logistic regression. When lambda is above 0, the penalty starts to shrink the parameter estimates. So a full search means trying many values of both lambda and alpha.

Step by step

  1. Load the library and fix the random seed, so the made-up data comes out the same every time. 
    library(glmnet)
set.seed(42)
  2. Make a data set with 1,000 samples and 5,000 parameters, where only the first 15 parameters carry signal. The matrix x holds 5 million random values from a standard normal distribution. The vector y is the row sum of the first 15 columns plus a little noise. 
    n <- 1000       # 1000 samples
p <- 5000       # 5000 parameters
real_p <- 15    # only 15 of them are useful

x <- matrix(rnorm(n*p), nrow=n, ncol=p)
y <- apply(x[, 1:real_p], 1, sum) + rnorm(n)

    Python equivalent

    import numpy as np
rng = np.random.default_rng(42)
n, p, real_p = 1000, 5000, 15
X = rng.standard_normal((n, p))
y = X[:, :real_p].sum(axis=1) + rng.standard_normal(n)
  3. Split the rows into a training set and a testing set. The sample function picks two thirds of the row numbers, and the minus sign selects everything that was not picked. 
    train_rows <- sample(1:n, .66*n)
x.train <- x[train_rows, ]
x.test  <- x[-train_rows, ]
y.train <- y[train_rows]
y.test  <- y[-train_rows]

    Python equivalent

    from sklearn.model_selection import train_test_split
X_train, X_test, y_train, y_test = train_test_split(
    X, y, train_size=0.66, random_state=42)
  4. Fit ridge regression with cv.glmnet. The cv part means 10-fold cross-validation is used to find good values for lambda. Note that cv.glmnet does not take formula notation, so x and y go in separately. 
    alpha0.fit <- cv.glmnet(x.train, y.train, type.measure="mse",
                        alpha=0, family="gaussian")

    Here type.measure="mse" says to judge the folds by mean squared error, and family="gaussian" says this is linear regression. For logistic regression you would use "deviance" and "binomial".

  5. Predict on the testing data and measure the error. The s argument is the size of the penalty, and here it is set to lambda.1se, the simplest model within one standard error of the best one. 
    alpha0.predicted <- predict(alpha0.fit, s=alpha0.fit$lambda.1se, newx=x.test)
mean((y.test - alpha0.predicted)^2)
# 14.47...
  6. Repeat the same two calls with alpha=1 for lasso and alpha=0.5 for elastic net. Everything else stays the same, so the three results can be compared fairly. 
    alpha1.fit <- cv.glmnet(x.train, y.train, type.measure="mse",
                        alpha=1, family="gaussian")
alpha1.predicted <- predict(alpha1.fit, s=alpha1.fit$lambda.1se, newx=x.test)
mean((y.test - alpha1.predicted)^2)      # 1.19...

alpha0.5.fit <- cv.glmnet(x.train, y.train, type.measure="mse",
                          alpha=0.5, family="gaussian")
alpha0.5.predicted <- predict(alpha0.5.fit, s=alpha0.5.fit$lambda.1se, newx=x.test)
mean((y.test - alpha0.5.predicted)^2)    # 1.24...

    Python equivalent (scikit-learn picks the penalty size by cross-validation too)

    from sklearn.linear_model import RidgeCV, LassoCV, ElasticNetCV
from sklearn.metrics import mean_squared_error

ridge = RidgeCV(alphas=np.logspace(-3, 3, 100), cv=10).fit(X_train, y_train)
lasso = LassoCV(cv=10, random_state=42).fit(X_train, y_train)
enet  = ElasticNetCV(l1_ratio=0.5, cv=10, random_state=42).fit(X_train, y_train)

for name, m in [("ridge", ridge), ("lasso", lasso), ("elastic", enet)]:
    print(name, mean_squared_error(y_test, m.predict(X_test)))
  7. Now test many values of alpha, not just three. A loop over the integers 0 to 10 gives alpha values of 0, 0.1, up to 1, and each fit is stored in a list under its own name. 
    list.of.fits <- list()
for (i in 0:10) {
  fit.name <- paste0("alpha", i/10)
  list.of.fits[[fit.name]] <- cv.glmnet(x.train, y.train,
                                        type.measure="mse",
                                        alpha=i/10, family="gaussian")
}
  8. Loop a second time to predict with the testing data, compute each mean squared error, and stack the rows into a results table. Printing results shows alpha, the error, and the name of the fit. 
    results <- data.frame()
for (i in 0:10) {
  fit.name <- paste0("alpha", i/10)
  predicted <- predict(list.of.fits[[fit.name]],
                       s=list.of.fits[[fit.name]]$lambda.1se, newx=x.test)
  mse <- mean((y.test - predicted)^2)
  temp <- data.frame(alpha=i/10, mse=mse, fit.name=fit.name)
  results <- rbind(results, temp)
}
results

    Python equivalent (l1_ratio in scikit-learn plays the role of alpha in glmnet)

    ratios = np.linspace(0.01, 1.0, 11)
enet_cv = ElasticNetCV(l1_ratio=list(ratios), cv=10,
                       random_state=42).fit(X_train, y_train)
print(enet_cv.l1_ratio_, enet_cv.alpha_,
      mean_squared_error(y_test, enet_cv.predict(X_test)))

Formulas

The glmnet penalty
$$ \text{RSS} \;+\; \lambda\left[\;\frac{1-\alpha}{2}\sum_{j=1}^{p}\beta_j^{2}\;+\;\alpha\sum_{j=1}^{p}\left|\beta_j\right|\;\right] $$

Symbols: RSS is the sum of squared residuals, the usual least squares fit measure. \(\beta_j\) is the estimate for parameter \(j\), and \(p\) is the number of parameters. \(\lambda\) is the single penalty size. \(\alpha\) is the mix, from 0 to 1. What it tells you: alpha slides the weight between the squared ridge term and the absolute lasso term, and lambda decides how hard either term pushes.

Mean squared error
$$ \text{MSE} = \frac{1}{m}\sum_{i=1}^{m}\left(y_i - \hat{y}_i\right)^{2} $$

Symbols: \(y_i\) is a true value in the testing set, \(\hat{y}_i\) is the predicted value, and \(m\) is the number of testing samples. What it tells you: it is the sum of the squared residuals divided by the sample size, and lower is better.

Worked example from the video

Example

The data has 1,000 samples and 5,000 parameters, but only the first 15 columns of x affect y. The other 4,985 columns are noise. Two thirds of the rows train the models, one third tests them.

Ridge with alpha 0 gives a test error of 14.47. Lasso with alpha 1 gives 1.19. Elastic net with alpha 0.5 gives 1.24. Lasso is far better here, and it stays the best when all eleven alpha values are compared in the loop.

Common mistakes and subtle points

Watch out lambda.1se and lambda.min are not the same. lambda.min gives the smallest cross-validation error. lambda.1se gives the simplest model within one standard error of that best value. Josh uses lambda.1se for all three fits so the comparison stays consistent.
Watch out Ridge regression never sets a parameter to exactly zero, so calling lambda.1se the model with the fewest non-zero parameters only really bites for lasso and elastic net. It is still a valid, more conservative choice of lambda for ridge.
Watch out cv.glmnet does not accept formula notation like lm or glm. You must pass the matrix and the response vector separately. Also switch type.measure to "deviance" and family to "binomial" for logistic regression.
Watch out The numbers move a little between runs, because the starting parameter values are random. Always call set.seed before you compare results. Also mind the naming clash in Python: glmnet's alpha is scikit-learn's l1_ratio, and glmnet's lambda is scikit-learn's alpha.

If they ask you in an interview

How does glmnet parameterise elastic net?
It uses one lambda and one alpha instead of two lambdas. Lambda controls the total strength of the penalty. Alpha, from 0 to 1, controls the mix, where 0 is pure ridge and 1 is pure lasso. Anything in between blends the two.
What is lambda.1se and when would you use it?
It is the largest lambda whose cross-validation error is still within one standard error of the minimum. Statistically it is hard to tell apart from lambda.min, but it gives a simpler model with fewer non-zero parameters. I use it when I want a more stable, more interpretable fit, and lambda.min when raw predictive error is all that matters.
Why did lasso clearly beat ridge in this example?
The data had 5,000 parameters but only 15 of them carried any signal. Lasso can drive the other 4,985 coefficients to exactly zero, so the noise is removed. Ridge only shrinks them, so thousands of small wrong contributions add up. The test error was about 14.5 for ridge against 1.19 for lasso.
How do you choose alpha in practice?
You treat it as a hyperparameter and search over it. In the video a loop fits eleven models with alpha from 0 to 1 in steps of 0.1, each with its own cross-validated lambda. Then you score every fit on held-out data and keep the best. In scikit-learn the same search is a list of l1_ratio values passed to ElasticNetCV.

Recap in 30 seconds

  • The glmnet package fits ridge, lasso and elastic net with one lambda and one alpha.
  • Alpha equal to 0 is ridge, alpha equal to 1 is lasso, and values in between mix both penalties.
  • Lambda sets the strength of the penalty, and lambda equal to 0 returns plain least squares.
  • The function cv.glmnet uses 10-fold cross-validation to find good lambdas, and needs x and y passed separately.
  • The predict function applies a fit to the test data at a chosen lambda, usually lambda.1se here.
  • On the made-up data the errors were about 14.47 for ridge, 1.24 for elastic net and 1.19 for lasso.
  • Lasso won because only 15 of the 5,000 parameters mattered, and lasso can delete the rest.
  • To find the best alpha, loop over many values, score each one on the testing set, and compare.
