The Introduction to PyTorch

▶ Watch on YouTube Also in: Neural Networks / Deep Learning (video 29)

Josh codes a small neural network in PyTorch, checks that it works, and then trains one of its parameters with backpropagation. It is the basic pattern behind almost every PyTorch model.

In one breath

A neural network in PyTorch is a class that inherits from nn.Module. Its __init__ method stores each weight and bias as a tensor wrapped in nn.Parameter. Its forward method turns an input into an output. Josh rebuilds the drug dosage network from an earlier video and graphs its output to confirm it works. He then sets the final bias to 0 and lets stochastic gradient descent find its best value again. After 34 steps the bias reaches -16.0019, very close to the original -16.

The main idea

The data come from the earlier video on the ReLU activation function. Low and high drug doses were not effective against a virus, but a medium dose was. A small network with two ReLU nodes bends its output into a pointy shape that fits these three points.

To code this network, Josh creates a class called BasicNN that inherits from nn.Module. The __init__ method creates every weight and bias as a parameter. A parameter is a value the network owns and can optionally optimize. The forward method connects the input, the weights, the biases and the activation functions to compute the output. This is called a forward pass.

Each value is stored as a tensor. Tensors give the network fast arithmetic and automatic differentiation, which means PyTorch can work out derivatives for us. The flag requires_grad, short for "requires gradient", decides whether a parameter will be optimized.

Step by step

  1. Import the modules. torch creates tensors, and torch.nn makes weights and biases part of the network. torch.nn.functional gives the activation functions, and SGD (stochastic gradient descent) fits the network. Matplotlib and seaborn only draw graphs.
  2. Create BasicNN, inheriting from nn.Module. In __init__, first call the parent's initialization method, then create each weight and bias as a parameter with requires_grad=False, since none need optimizing yet.
  3. Write forward. Multiply the input by a weight, add a bias, pass it through F.relu, and scale the result. Do this for the top and bottom nodes, add both to the final bias, and pass the sum through a last ReLU.
  4. Test the network. Use torch.linspace to make 11 doses from 0 to 1, pass them to the model, and draw the outputs. The bent shape matches the earlier video.
  5. Copy the class to BasicNN_train. Set the final bias to 0.0 with requires_grad=True. This tells PyTorch that this parameter should be optimized.
  6. Create the training data, then an SGD optimizer on model.parameters() with a learning rate of 0.1.
  7. Run the training loop: for each epoch, run every point through the model, compute the loss, call loss.backward(), then step and zero the derivatives. Stop early when the total loss is tiny.

The code below matches the class Josh writes. The weight values come from the earlier ReLU video.

import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.optim import SGD

class BasicNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.w00 = nn.Parameter(torch.tensor(1.7), requires_grad=False)
        self.b00 = nn.Parameter(torch.tensor(-0.85), requires_grad=False)
        self.w01 = nn.Parameter(torch.tensor(-40.8), requires_grad=False)
        self.w10 = nn.Parameter(torch.tensor(12.6), requires_grad=False)
        self.b10 = nn.Parameter(torch.tensor(0.0), requires_grad=False)
        self.w11 = nn.Parameter(torch.tensor(2.7), requires_grad=False)
        self.final_bias = nn.Parameter(torch.tensor(-16.), requires_grad=False)

    def forward(self, input):
        input_to_top_relu = input * self.w00 + self.b00
        top_relu_output = F.relu(input_to_top_relu)
        scaled_top_relu_output = top_relu_output * self.w01

        input_to_bottom_relu = input * self.w10 + self.b10
        bottom_relu_output = F.relu(input_to_bottom_relu)
        scaled_bottom_relu_output = bottom_relu_output * self.w11

        input_to_final_relu = (scaled_top_relu_output
                               + scaled_bottom_relu_output
                               + self.final_bias)
        output = F.relu(input_to_final_relu)
        return output

This is the training loop. The second figure shows the same flow as a picture.

inputs = torch.tensor([0., 0.5, 1.])
labels = torch.tensor([0., 1., 0.])

model = BasicNN_train()
optimizer = SGD(model.parameters(), lr=0.1)
print("Final bias, before optimization: " + str(model.final_bias.data))

for epoch in range(100):
    total_loss = 0
    for iteration in range(len(inputs)):
        input_i = inputs[iteration]
        label_i = labels[iteration]
        output_i = model(input_i)
        loss = (output_i - label_i)**2   # squared residual
        loss.backward()                  # adds to stored derivatives
        total_loss += float(loss)
    if total_loss < 0.0001:
        print("Num steps: " + str(epoch))
        break
    optimizer.step()
    optimizer.zero_grad()
    print("Step: " + str(epoch) + " Final Bias: " + str(model.final_bias.data))

print("Final bias, after optimization: " + str(model.final_bias.data))

Formulas

Forward pass
$$ \hat{y} = \text{ReLU}\big(w_{01}\,\text{ReLU}(x\,w_{00}+b_{00}) + w_{11}\,\text{ReLU}(x\,w_{10}+b_{10}) + b_{\text{final}}\big) $$

Symbols: \(x\) is the dose. \(w\) values are weights and \(b\) values are biases. ReLU outputs its input when positive and 0 otherwise. \(\hat{y}\) is the predicted effectiveness. What it tells you: this is exactly what forward computes, one line per arrow in the first figure.

Total loss for one epoch
$$ \text{total loss} = \sum_{i=1}^{3} (\hat{y}_i - y_i)^2 $$

Symbols: \(\hat{y}_i\) is the model's output for point \(i\). \(y_i\) is its known label. Each term is a squared residual, the squared difference between prediction and truth. What it tells you: a large value means a poor fit and a small value means a good fit.

What loss.backward() accumulates
$$ \frac{\partial\,\text{total loss}}{\partial b_{\text{final}}} = \sum_{i=1}^{3} \frac{\partial (\hat{y}_i - y_i)^2}{\partial b_{\text{final}}} $$

Symbols: \(\partial / \partial b_{\text{final}}\) is the derivative with respect to the final bias. What it tells you: each call to loss.backward() adds one term of this sum. optimizer.step() then uses the summed derivative, scaled by the learning rate of 0.1, to take a small step toward a better final bias.

Worked example from the video

Example

Training data. Inputs are the doses 0, 0.5 and 1. Labels are the observed effectiveness 0, 1 and 0.

The trained network. With the final bias at -16, the dose 0.5 gives an effectiveness of 1, which is correct. Here is why, using the weights in the code: the top node gets \(0.5 \times 1.7 - 0.85 = 0\), so it contributes 0. The bottom node gets \(0.5 \times 12.6 + 0 = 6.3\), scaled by 2.7 gives about 17. Adding -16 gives about 1.

Breaking it. Set the final bias to 0. The same dose now gives an effectiveness of about 17, which is way too high. So the network needs training.

One pass of the inner loop. For the first point, the dose is 0 and the label is 0. The prediction is also 0, so the squared residual is \((0-0)^2 = 0\). The second and third points add their own squared residuals and derivatives.

Result. The printout starts with a final bias of 0. After 34 steps the total loss is tiny and the final bias is -16.0019, very close to -16. Graphing the trained model shows it fits the three points again.

Common mistakes and subtle points

Watch out loss.backward() accumulates derivatives. Each call adds to the ones already stored in the model, even though loss is a brand new variable each time. This works because the loss is built from the model's output, and the model keeps track of the derivatives.
Watch out Forgetting optimizer.zero_grad() is a bug. Without it, the next epoch's derivatives are added to the old ones from the previous step, and the steps go wrong.
Watch out total_loss does not accumulate on its own. You must add each squared residual to it yourself.
Watch out A tensor that carries a gradient cannot go straight into seaborn. Call .detach() to get a new tensor with only the values.

If they ask you in an interview

How do you define a neural network in PyTorch?
I write a class that inherits from nn.Module. In __init__ I call the parent's initializer and create the weights and biases as nn.Parameter tensors. In forward I compute the output from the input. Calling the model on data runs forward for me.
What does requires_grad control?
It tells PyTorch whether a parameter should be optimized. When it is true, PyTorch tracks derivatives for that parameter, and the optimizer will update it. In the dosage example only the final bias had it set to true, so SGD changed only that value.
Why do we call optimizer.zero_grad()?
Because loss.backward() adds new derivatives to the ones already stored. That is useful within one epoch, where we want the sum over all points. But after optimizer.step() we must clear them, or the next epoch would mix in old derivatives.
Walk me through one epoch of the training loop.
For each training point I run the input through the model, compute the loss, call loss.backward(), and add the loss to a running total. If the total loss is tiny, I stop. Otherwise I call optimizer.step() to move the parameters a small step, then optimizer.zero_grad() to reset the derivatives.
What is an epoch?
An epoch is one full pass of the optimization code over all of the training data. In the video that means running all three dosage points through the model once. Training was allowed up to 100 epochs but stopped early after 34 steps.

Recap in 30 seconds

  • A PyTorch network is a class that inherits from nn.Module.
  • __init__ creates weights and biases as nn.Parameter tensors, and forward computes the output.
  • Setting requires_grad=True marks a parameter for optimization.
  • The SGD optimizer receives model.parameters() and a learning rate, here 0.1.
  • Each epoch runs every point through the model, computes the loss, and calls loss.backward(), which adds up derivatives.
  • Then optimizer.step() updates the parameters and optimizer.zero_grad() clears the stored derivatives.
  • Starting from 0, the final bias reached -16.0019 after 34 steps, close to the true -16.
