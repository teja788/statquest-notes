Clustering with DBSCAN

▶ Watch on YouTube

DBSCAN groups points by how tightly they are packed. It finds clusters that wrap around each other, and it leaves lonely points out as outliers.

In one breath

Josh plots people by weight and height. Your eye sees two clumps, one wrapped around the other, plus a few points sitting far away. A simple method like k-means struggles with wrapped clusters, and with four or more features you cannot even draw the graph. DBSCAN copies what your eye does. It counts how many neighbours each point has, calls the crowded points core points, and then grows clusters outward from them.

The main idea

Imagine we measure the weight and height of many people. We put weight on the x-axis and height on the y-axis, and plot one dot per person. By eye we see two clumps of dots that are fairly dense. A few dots sit far away from everyone else, and those look like outliers.

Here the two clumps are nested. That means the green cluster wraps around the blue cluster, like a ring around a ball. A standard method like k-means clustering can have trouble with this shape. It may cut the picture in a strange place, and give the blue cluster some points that clearly belong to the green ring.

There is a second problem. This graph uses only two measurements. Add each person's age and we need a third axis, which is awkward on a flat screen. With four or more measurements we cannot draw the graph at all.

DBSCAN works from density, which is just how crowded a small region is. Clusters live in crowded regions, and outliers live in empty ones. Counting neighbours works in any number of dimensions, so DBSCAN keeps working when the picture is impossible to draw.

Step by step

  1. Choose a radius. Draw a circle of that radius around each point, and count how many other points the circle overlaps. The radius is set by you, so expect to try a few values.
  2. Choose the smallest number of neighbours a crowded point must have. In this video a point needs at least 4 close points. This number is also set by you.
  3. Label every point. A point with enough neighbours is a core point. Every other point is a non-core point.
  4. Pick one core point at random. It becomes the start of the first cluster.
  5. Add the core points that are close to the cluster. Each new core point can pull in more core points near it, so the cluster grows outward.
  6. Stop growing when no core point can be added. At this moment every point in the cluster is a core point.
  7. Now add the non-core points that are close to a core point in the cluster. They join the cluster, but they cannot pass it on to their own neighbours.
  8. Take a core point that has no cluster yet and start the next cluster. Repeat until every core point belongs to a cluster. The non-core points that are close to no core point are called outliers.

Formulas

The video states the rules in words and pictures. These three lines write the same rules down.

Distance between two points
$$ d(p,q)=\sqrt{\sum_{i=1}^{m}\left(p_i-q_i\right)^2} $$

Symbols: \(p\) and \(q\) are two points, for example two people. \(m\) is how many measurements each person has, such as weight, height and age. \(p_i\) is the value of measurement \(i\) for person \(p\). \(d(p,q)\) is the straight-line distance between them. What it tells you: distance is just arithmetic, so it works with 2 measurements or with 200, even when no graph can be drawn.

The points inside the circle
$$ N_\varepsilon(p)=\{\;q\in D\;:\;q\neq p,\;d(p,q)\le\varepsilon\;\} $$

Symbols: \(\varepsilon\) is the radius of the circle you draw around a point, and you choose it. \(D\) is the whole set of points. \(N_\varepsilon(p)\) is the group of other points that fall inside the circle around \(p\). What it tells you: this group is what you count when you ask how crowded the area around a point is.

The core point test
$$ \left|N_\varepsilon(p)\right|\;\ge\;\text{minPts}\quad\Longrightarrow\quad p\ \text{is a core point} $$

Symbols: \(\left|N_\varepsilon(p)\right|\) is the number of points inside the circle around \(p\). \(\text{minPts}\) is the smallest count you accept, and you choose it; in the video it is 4. What it tells you: two numbers, \(\varepsilon\) and \(\text{minPts}\), decide the whole clustering, because everything else follows from which points pass this test.

Worked example from the video

Example

Josh draws an orange circle of the chosen radius around one red point. The circle touches 8 other points, so that point is close to 8 points. He repeats this for more points and gets counts of 5, 6 and 7. One point is close to only 2 points, and one point sits alone, so its count is 0.

The rule here is at least 4 close points. The points with 8, 5, 6 and 7 neighbours all pass, so they are core points. The points with 2 and 0 neighbours fail, so they are non-core.

Now pick a core point at random and call it cluster 1. Core points close to it join and extend it, and their neighbours extend it again, until no core point is left to add. At that moment every member of cluster 1 is a core point. Then the non-core points that touch a core point of cluster 1 are added.

One non-core point sits next to a non-core point that just joined. It is not close to any core point, so it stays out. The core points that never touched cluster 1 are close to each other, so they start cluster 2, and their nearby non-core points join it. When all core points have a cluster, the leftover non-core points are labelled outliers.

Common mistakes and subtle points

Watch out Both settings are yours to choose. The circle radius and the minimum number of close points are not learned from the data. Josh says plainly that you may need to fiddle with each of them, so treat DBSCAN results as a function of those two numbers.
Watch out Core points and non-core points do not behave the same way. A core point pulls its neighbours into the cluster and keeps the chain going. A non-core point may join a cluster, but the cluster stops there and never spreads through it.
Watch out Clusters are built one after another, not all at once. Suppose a non-core point is close to core points in two different clusters. It joins whichever cluster is built first, and after that it is no longer available to the other one.
Watch out Not every point gets a cluster. Points that are non-core and far from all core points are returned as outliers. That is the intended output, not a failure of the method.

If they ask you in an interview

Why would you use DBSCAN instead of k-means?
Because DBSCAN works from density rather than from distance to a centre. That lets it find nested clusters, like a ring wrapped around a ball, where k-means would cut straight through the ring. DBSCAN also reports outliers instead of forcing every point into a group.
What is a core point?
A core point is a point with a crowded neighbourhood. You draw a circle of a chosen radius around it and count the other points inside. If that count reaches your chosen minimum, four in the video, the point is a core point. Core points are the only points that can grow a cluster.
How does a cluster actually form?
You start from a random core point. Core points inside its circle join the cluster and then extend it to their own neighbours, and this repeats until no more core points can be reached. Only then do you add the non-core points that sit next to a core point in the cluster. Those points join, but they do not carry the cluster any further.
Can DBSCAN give different answers on the same data?
The core points are fixed by the two settings, so the dense parts of each cluster are stable. The edges can move, because clusters are made one at a time and a non-core point near two clusters goes to whichever one is built first. Since the starting core point is picked at random, the assignment of those border points can change between runs.

Recap in 30 seconds

  • Your eye finds clusters by density, and DBSCAN copies that idea with counting.
  • You choose two things: a circle radius, and the smallest number of close points a crowded point must have.
  • A point that meets the minimum is a core point, and everything else is non-core.
  • A random core point starts a cluster, and nearby core points join it and extend it further.
  • When no core point can be added, the non-core points next to core points join, but they do not extend the cluster.
  • The remaining core points start the next cluster, and the process repeats until every core point is assigned.
  • Non-core points that touch no core point are reported as outliers.
  • Because it only needs distances, DBSCAN finds nested clusters in data you cannot plot.
