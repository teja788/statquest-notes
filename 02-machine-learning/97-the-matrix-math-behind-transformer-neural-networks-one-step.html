The matrix math behind transformer neural networks, one step at a time

▶ Watch on YouTube Also in: Neural Networks / Deep Learning (video 28)

This video rewrites every step of an encoder-decoder transformer as matrix multiplication. Josh says the matrix form makes coding transformers, and neural networks in general, far easier to understand.

In one breath

The example translates "<SOS> let's go" into "vamos <EOS>". Embeddings, queries, keys and values are each one matrix product for all tokens. Attention is Q times the transpose of K, scaled by the square root of dk, passed through SoftMax row by row, then multiplied by V. The decoder adds a mask so no token can peek at tokens that come after it. Encoder-decoder attention is the same math, but K and V come from the encoder's output.

The main idea

A transformer does the same small calculations for every token. If we stack the tokens as rows of a matrix, one matrix multiplication does the work for all of them at once. This also lets training run in parallel.

In this example each token has two values, so every token matrix has two columns. The figure follows the shapes through attention in the encoder, which has three tokens.

Step by step

  1. Word embeddings. Each input token becomes a one-hot row: a 1 in its own column and 0 everywhere else. The input vocabulary is SOS, let's, to and go, so this matrix is 3×4. Multiplying it by the 4×2 embedding weight matrix simply picks out each token's two embedding values.
  2. Positional encoding. We add the matching y-axis values from the sine and cosine curves, element by element. In practice these values are precomputed and stored in a lookup table.
  3. Queries, keys and values. The encoded matrix X times a 2×2 query weight matrix gives Q. Different weights give K and V the same way. The weights carry a transpose symbol because PyTorch prints them in a form that must be transposed.
  4. Q times Kᵀ. Each entry is a dot product of one token's query and one token's key: multiply matching numbers, then add. A dot product is an unscaled similarity, closely related to cosine similarity.
  5. Scale. Divide every similarity by \(\sqrt{d_k}\), where \(d_k\) is the number of values per token, here 2.
  6. SoftMax each row. Each row now sums to 1, so it reads as percentages: how much each token relates to every other token.
  7. Multiply by V. Each row of percentages mixes the value columns. The result is the self-attention scores for every token.
  8. Residual connection. Add back the encodings from right after positional encoding. This is the encoder's output.
  9. Decoder input. During training, the decoder gets SOS and vamos. Its vocabulary has five tokens (SOS, ir, vamos, y, EOS). So a 2×5 one-hot matrix times a 5×2 embedding matrix gives two embeddings, plus positional encoding.
  10. Masked self-attention. The decoder computes Q, K, V and the scaled similarities with its own weights. Before SoftMax it adds a mask, so each token uses only itself and earlier tokens. Another residual connection follows.
  11. Encoder-decoder attention. Q comes from the decoder values. K and V come from the encoder's output, each with its own weights. The attention math is otherwise unchanged. Another residual connection follows.
  12. Output. A fully connected layer has two inputs and five outputs, one per output token. It is a matrix product, plus a bias added to each column. A final SoftMax gives one row of probabilities per decoder copy.

Formulas

Queries, keys and values
$$ Q = X W_Q^{T}, \qquad K = X W_K^{T}, \qquad V = X W_V^{T} $$

Symbols: \(X\) is the matrix of encoded tokens (word embedding plus position), one row per token. \(W_Q, W_K, W_V\) are the learned query, key and value weight matrices. \(T\) means transpose: swap rows and columns. What it tells you: one multiplication computes the queries (or keys, or values) for every token at once.

Attention
$$ \text{Attention}(Q,K,V) = \text{SoftMax}\!\left(\frac{QK^{T}}{\sqrt{d_k}} + M\right) V $$

Symbols: \(QK^{T}\) holds the dot products of every query with every key. \(d_k\) is the number of values per token in the key matrix (2 here). \(M\) is the mask: 0 where a value may be used and \(-\infty\) where it must be ignored. The encoder has no mask, so there \(M\) is all zeros. SoftMax turns each row into percentages that sum to 1. \(V\) is the value matrix. What it tells you: each token's output is a mix of all values, weighted by how similar its query is to each key.

Worked example from the video

Example

Query for SOS. The encoded SOS token is (1.16, 0.23). The first column of query weights is (2.22, 0.17) and the second column is (0.41, −0.51).

\(1.16 \times 2.22 + 0.23 \times 0.17 = 2.575 + 0.039 = 2.61\)
\(1.16 \times 0.41 + 0.23 \times (-0.51) = 0.476 - 0.117 = 0.36\)

So the query for SOS is (2.61, 0.36).

SOS row of Q·Kᵀ. The unscaled similarities between the query for SOS and the keys for SOS, let's and go are −4.49, 2.05 and −27.4. Dividing by \(\sqrt{2} \approx 1.414\) gives about −3.17, 1.45 and −19.4. SoftMax turns these into 1%, 99% and 0%. So SOS is 1% similar to itself, 99% to let's, and 0% to go.

First attention score for SOS. Take 1% of the first value for SOS, add 99% of the first value for let's, and add 0% of the first value for go. The result is 1.54.

Decoder mask. The query for SOS times the key for vamos gives 0.12. Scaled, this is \(0.12 / 1.414 \approx 0.08\). The mask adds \(-\infty\) to that cell, so SoftMax gives SOS 100% similarity to itself and 0% to vamos. The vamos row gets zeros in the mask and uses both tokens.

Final output. The first row of the last SoftMax has 1 for vamos and 0 for the rest, so vamos is the first output token. In the second row, EOS has the highest value, so the transformer stops.

Common mistakes and subtle points

Watch out We transpose K for two reasons. Without it, the shapes would not line up. More importantly, it makes each entry of the product a query-key dot product.
Watch out Dividing by \(\sqrt{d_k}\) is not a careful normalisation. In the example the scaled values still range from 5.01 to −66.2. The original transformer authors still reported that it improved performance.
Watch out During training, the decoder processes SOS and vamos at the same time. This is called teacher forcing: the second decoder copy gets the known token vamos, whatever the first copy outputs. The mask stops SOS from using vamos, because after training SOS will not know what comes next.

If they ask you in an interview

Why is attention computed as Q times K transpose?
Each row of Q is a token's query and each row of K is a token's key. Transposing K turns the keys into columns, so each entry of the product is the dot product of one query and one key. That gives an unscaled similarity for every pair of tokens in one multiplication.
What does the mask do in decoder self-attention?
It adds zero to the similarities a token may use and minus infinity to the ones it must ignore. After SoftMax, the ignored ones become zero percent. So during training a token can look at itself and earlier tokens, but never peek at later ones.
How does encoder-decoder attention differ from self-attention?
The math is the same. The difference is where the inputs come from. Queries are built from the decoder's values, while keys and values are built from the encoder's output, each with their own weight matrices.
What is dk and why divide by its square root?
It is the number of values per token in the key matrix, 2 in the video's example. Dividing by its square root is a simple scaling step. It does not normalise the values in any systematic way, but the original authors said it improved performance.

Recap in 30 seconds

  • Word embedding is a one-hot matrix times an embedding weight matrix, and positional encoding is added element by element.
  • Q, K and V are the encodings multiplied by three separate weight matrices.
  • Attention is SoftMax of Q·Kᵀ divided by √dk, plus a mask in the decoder, multiplied by V.
  • Each SoftMax row sums to 1 and tells how much one token relates to each other token.
  • Residual connections add the input of each attention step back to its output.
  • Encoder-decoder attention takes Q from the decoder and K and V from the encoder.
  • A fully connected layer with bias and a final SoftMax picks the output token for each decoder row.
