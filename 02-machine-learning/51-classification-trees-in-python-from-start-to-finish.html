Classification Trees in Python from Start to Finish

▶ Watch on YouTube

Josh builds one complete classification tree in Python, from a raw file to a pruned, readable tree that predicts heart disease.

In one breath

The data is the heart disease set from the UCI machine learning repository. Josh loads it with pandas, names the columns, finds missing values hidden as question marks, and drops those six rows. He then one-hot encodes the categorical columns, because scikit-learn trees do not natively support categorical data. A first tree grown without limits is huge and overfits the training data. Cost complexity pruning, with cross-validation to choose the pruning strength alpha, gives a small tree that scores better on the test data.

The main idea

Classification trees are useful when you must explain a prediction, not just make it. Each split is a plain question about one column, so you can trace any patient down the tree. Josh notes that doctors use them for this reason, and that they also show which features matter most.

Most of the work is not the model. It is getting the data into the shape scikit-learn expects. That means finding missing values, deciding what to do with them, and turning category codes into columns of zeros and ones.

The second big idea is pruning. A tree with no limits keeps splitting until the leaves are almost pure. It then memorises the training data instead of learning the pattern. Cost complexity pruning fixes this with one number, alpha, that charges a price for every leaf. Larger alpha means a smaller tree.

Step by step

  1. Load pandas for the data, NumPy for means and standard deviations, matplotlib for plots, and the scikit-learn pieces for the tree.

    import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
from sklearn.tree import DecisionTreeClassifier, plot_tree
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.metrics import confusion_matrix, plot_confusion_matrix

  2. Read the heart disease file into a data frame, then replace the column numbers with the names from the UCI page.

    df = pd.read_csv('processed.cleveland.data', header=None)
df.columns = ['age', 'sex', 'cp', 'restbp', 'chol', 'fbs', 'restecg',
              'thalach', 'exang', 'oldpeak', 'slope', 'ca', 'thal', 'hd']
df.head()

  3. Check the data types. Two columns, ca and thal, come back as object, which means they mix numbers with something else.

    df.dtypes
df['ca'].unique()     # 0.0, 3.0, 2.0, 1.0, '?'
df['thal'].unique()   # 6.0, 3.0, 7.0, '?'

  4. The question marks are the missing values. Count the affected rows, then keep only the rows without them.

    len(df.loc[(df['ca'] == '?') | (df['thal'] == '?')])   # 6
len(df)                                                # 303

df_no_missing = df.loc[(df['ca'] != '?') & (df['thal'] != '?')]
len(df_no_missing)                                     # 297

  5. Split the columns into X, the features used to predict, and y, the heart disease column being predicted.

    X = df_no_missing.drop('hd', axis=1).copy()
y = df_no_missing['hd'].copy()

  6. One-hot encode the four categorical columns that have more than two categories. get_dummies turns each one into a set of zero or one columns.

    X_encoded = pd.get_dummies(X, columns=['cp', 'restecg', 'slope', 'thal'])
X_encoded.head()   # cp becomes cp_1.0, cp_2.0, cp_3.0, cp_4.0

  7. The target holds five levels, zero plus four grades of disease. Fold every value above zero into one, so the tree does simple yes or no classification.

    y_not_zero_index = y > 0
y[y_not_zero_index] = 1
y.unique()   # array([0, 1])

  8. Split into training and test sets, fit a tree with no limits, and score it on the test set with a confusion matrix.

    X_train, X_test, y_train, y_test = train_test_split(X_encoded, y, random_state=42)

clf_dt = DecisionTreeClassifier(random_state=42)
clf_dt = clf_dt.fit(X_train, y_train)

plot_confusion_matrix(clf_dt, X_test, y_test,
                      display_labels=["Does not have HD", "Has HD"])

  9. Ask the tree for the alphas worth trying, drop the largest one, and build a pruned tree for each remaining alpha.

    path = clf_dt.cost_complexity_pruning_path(X_train, y_train)
ccp_alphas = path.ccp_alphas
ccp_alphas = ccp_alphas[:-1]        # the largest alpha leaves only the root

clf_dts = []
for ccp_alpha in ccp_alphas:
    clf = DecisionTreeClassifier(random_state=0, ccp_alpha=ccp_alpha)
    clf.fit(X_train, y_train)
    clf_dts.append(clf)

  10. A single train and test split makes alpha look best near 0.016. Cross-validation scores each alpha on several different splits and moves the answer.

    alpha_loop_values = []
for ccp_alpha in ccp_alphas:
    clf = DecisionTreeClassifier(random_state=0, ccp_alpha=ccp_alpha)
    scores = cross_val_score(clf, X_train, y_train, cv=5)
    alpha_loop_values.append([ccp_alpha, np.mean(scores), np.std(scores)])

results = pd.DataFrame(alpha_loop_values,
                       columns=['alpha', 'mean_accuracy', 'std'])
results.plot(x='alpha', y='mean_accuracy', yerr='std',
             marker='o', linestyle='--')

  11. Read the best alpha off the curve, narrow the range, and convert it from a pandas series to a plain float.

    ideal_ccp_alpha = results[(results['alpha'] > 0.014)
                        & (results['alpha'] < 0.015)]['alpha']
ideal_ccp_alpha = float(ideal_ccp_alpha)

  12. Fit the final tree with that alpha, score it, and draw it. This tree is small enough to read node by node.

    clf_dt_pruned = DecisionTreeClassifier(random_state=42,
                                       ccp_alpha=ideal_ccp_alpha)
clf_dt_pruned = clf_dt_pruned.fit(X_train, y_train)

plot_confusion_matrix(clf_dt_pruned, X_test, y_test,
                      display_labels=["Does not have HD", "Has HD"])

plot_tree(clf_dt_pruned, filled=True, rounded=True,
          class_names=["No HD", "Yes HD"],
          feature_names=X_encoded.columns)

Formulas

Gini impurity of a node
$$ G = 1 - \sum_{i=1}^{k} p_i^{\,2} $$

Symbols: \(k\) is the number of classes, here two, and \(p_i\) is the share of the samples in that node belonging to class \(i\). What it tells you: Gini is zero when a node holds one class only, and near 0.5 for a two-class fifty-fifty node. In the drawn tree, darker colour means lower Gini, so a cleaner split.

Cost complexity score
$$ R_\alpha(T) = R(T) + \alpha\,|T| $$

Symbols: \(T\) is a tree, \(R(T)\) is its total weighted leaf impurity, \(|T|\) is its number of leaves, and \(\alpha\) is the price charged per leaf. What it tells you: Every extra leaf must lower the impurity by more than \(\alpha\), or it is cut. At \(\alpha = 0\) you keep the full tree; at the largest alpha only the root is left.

Josh points out why these alphas look small. The earlier StatQuest on pruning used regression trees scored by the sum of squared residuals, which can be a huge number. Gini stays between 0 and 1, so the useful alphas here are around 0.01 instead.

Worked example from the video

Example

The test set holds 75 patients: 42 without heart disease and 33 with it. The unpruned tree gets 31 of the 42 healthy patients right, which is 74 percent, and 26 of the 33 sick patients right, which is 79 percent.

After pruning with the cross-validated alpha near 0.014, the same test set gives 81 percent on the healthy patients and 85 percent on the sick ones. Overall accuracy moves from about \( (31+26)/75 = 76\% \) to about 83 percent.

The smaller tree wins. Its first split is on ca, the number of blood vessels lit up during fluoroscopy, at the threshold 0.5. That root node holds 118 patients without heart disease and 104 with it, so the class shown is "no heart disease". Further down, after ca, the thallium heart scan and oldpeak, one leaf is almost entirely patients without heart disease.

Common mistakes and subtle points

Watch out Do not feed coded categories to the tree as numbers. Chest pain is stored as 1, 2, 3, 4. Left as a float, the tree treats 4 as closer to 3 than to 1, which is not true for these labels. One-hot encoding removes that false order.
Watch out Missing data can hide as text. Here it is a question mark, which is why ca and thal show the object data type. Always print the unique values of any suspicious column.
Watch out Deal with missing rows before you split X from y and before the train and test split. Otherwise rows in X stop matching rows in y, and dropping rows late can unbalance the test set. Imputing values is the opposite: do that after the split.
Watch out Do not trust an alpha read off one train and test split. That single split suggested 0.016, but cross-validation showed some folds did badly there and preferred a value near 0.014. Also drop the largest alpha in the path, since it prunes the tree down to the root.

If they ask you in an interview

Why do you one-hot encode before a scikit-learn decision tree?
Scikit-learn trees split on numbers, so they read a category code as an ordered quantity. With chest pain coded 1 to 4, the tree would group 3 and 4 together as if they were similar. One-hot encoding gives each category its own zero or one column, so no category is nearer to any other. In pandas I use get_dummies, though ColumnTransformer is more common in production pipelines.
What is cost complexity pruning, and what does alpha control?
It scores a tree as its leaf impurity plus alpha times the number of leaves. Alpha is the price of keeping a leaf, so a split survives only if it buys more impurity reduction than it costs. Alpha of zero leaves the full tree, and a large alpha collapses it to the root. In scikit-learn I get the candidate values from cost_complexity_pruning_path and pass the chosen one as ccp_alpha.
Why use cross-validation to pick alpha?
Accuracy on a single test split is noisy, so the best alpha on that split may be lucky. In this example the single split pointed to 0.016, but across folds that value was unstable and a value near 0.014 did better on average. I loop over the candidate alphas, take the mean and standard deviation of the cross-validated scores, and pick from the plot. Grid search does the same job if I am tuning other parameters at the same time.
How did you know the first tree was overfitting?
The full tree was almost perfect on the training data but only about 76 percent accurate on the test data. That gap is the signal. After pruning, training accuracy dropped and test accuracy rose to roughly 83 percent, which confirms the big tree had memorised the training set rather than learned the pattern.
Why choose a single tree over a random forest here?
Interpretability. A pruned tree lets you show a clinician the exact path: number of vessels, then the thallium scan, then oldpeak. Random forests are similar but harder to interpret, because each prediction comes from many trees. For sheer interpretability and simplicity, a single tree is the best choice.

Recap in 30 seconds

  • The goal is to predict heart disease from the UCI heart disease data using a classification tree in scikit-learn.
  • Missing values appear as question marks in ca and thal, and the 6 affected rows of 303 are dropped, leaving 297.
  • The data is split into X, the predictors, and y, the heart disease column, only after the missing rows are removed.
