Machine Learning Fundamentals: Cross Validation

▶ Watch on YouTube

Cross validation is a simple way to compare machine learning methods on the same data. You cut the data into blocks, then let every block take a turn as the test set.

In one breath

Your data must do two jobs: train a method and test it. If you train and test on the same rows, the score is not honest. A single 75/25 split is better, but the block you hold back is an arbitrary choice. Cross validation tests on every block, one at a time. You compare methods by their summarised scores and keep the winner.

The main idea

Josh starts with heart disease data. Variables such as chest pain and good blood circulation predict whether a person has heart disease. Many methods can do this job: logistic regression, k-nearest neighbours, or support vector machines. We must decide which one to use.

The same data has to do two jobs. First we estimate the parameters of a method, such as the shape of a logistic regression curve. That job is called training. Second we check how well the fitted method labels new data. That job is called testing.

Using all the data for training leaves nothing to test with. Holding back the last 25 percent is better, but that choice is arbitrary. Cross validation ends the argument. It tests on every block, one at a time, and summarises the results at the end.

Step by step

  1. Divide the collected data into equal blocks. Josh draws four blocks in the video.
  2. Train the method on the first three blocks. Test it on the last block and record the score.
  3. Move the test block one place. Train on the other three blocks and record the score again.
  4. Repeat until every block has been the test block exactly once.
  5. Summarise the scores for each method and compare. The support vector machine did the best job here, so we use it.

Formulas

The video writes no equations. These three lines put its picture into symbols.

Summarised score
$$ \text{CV score} = \frac{1}{k}\sum_{i=1}^{k} S_i $$

Symbols: \(k\) is the number of blocks. \(S_i\) is the score the method got when block \(i\) was the test block. What it tells you: one number per method, built from every row of data, that you can compare across methods.

Size of each split
$$ \text{train fraction} = \frac{k-1}{k}, \qquad \text{test fraction} = \frac{1}{k} $$

Symbols: \(k\) is again the number of blocks. What it tells you: with \(k=4\) you train on 75 percent of the rows and test on 25 percent in each round.

Leave one out
$$ k = n $$

Symbols: \(n\) is the number of samples, that is patients, in the data. What it tells you: leave-one-out is not a separate technique. It is k-fold with one patient in each block.

Worked example from the video

Example

Josh cuts the heart disease data into four blocks. This is called four-fold cross validation. Round one trains on blocks 1, 2 and 3, then tests on block 4. Round two tests on block 3, round three on block 2, and round four on block 1.

Each round trains on \(3/4 = 75\%\) of the data and tests on \(1/4 = 25\%\). The four scores are summarised into one: \( \text{CV score} = (S_1+S_2+S_3+S_4)/4 \). Josh compares logistic regression, k-nearest neighbours and support vector machines this way. The support vector machine classified the test blocks best, so he keeps it.

Common mistakes and subtle points

Watch out Never judge a method on the data it was trained on. That score looks good and tells you nothing about new patients.
Watch out A single 75/25 split is one arbitrary choice out of many. A different quarter can give you a different winner.
Watch out The number of blocks is arbitrary. Four is easy to draw, ten is common in practice, and leave-one-out is the extreme.

If they ask you in an interview

Why can we not train and test on the same data?
Because the method already fits those rows, so the score is not honest. We need to know how it works on data it never saw. That is why we always hold some data back for testing.
Explain k-fold cross validation in a minute.
Split the data into k equal blocks. Train on k minus one blocks and test on the block you held back. Repeat until every block has been the test block once. Average the k scores to get one number per method, then compare methods on that number.
How do you choose the number of blocks?
There is no fixed rule, because the number is arbitrary. Ten folds is the common default in practice. At the extreme, k equals the number of samples, which is leave-one-out cross validation.
What is a tuning parameter, and how does cross validation help?
A tuning parameter is guessed, not estimated from the data. Ridge regression has one. We try several values, run 10-fold cross validation for each, and keep the value with the best score.

Recap in 30 seconds

  • Data must do two jobs: train a method, and test how well it works.
  • Training estimates parameters. Testing checks the result on unseen data.
  • Using all the data for training leaves nothing to test with.
  • A single 75/25 split is better, but the block you hold back is arbitrary.
  • Cross validation uses every block as the test block and summarises the scores.
  • Four blocks is four-fold; ten blocks is the usual choice; one sample per block is leave-one-out.
  • Cross validation also helps choose tuning parameters, such as the one in ridge regression.
