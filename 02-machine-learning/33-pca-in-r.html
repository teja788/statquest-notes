PCA in R

▶ Watch on YouTube

Josh runs a complete PCA in R with one function, prcomp. He builds a small fake gene data set, draws the PCA plot, measures how much variation each component holds, and finds the genes that drive the split.

In one breath

The prcomp function does the whole PCA in a single call. It expects samples as rows, so a gene matrix has to be transposed first. It returns three things you use: x holds the sample coordinates, sdev holds the spread of each component, and rotation holds the loading scores. Squaring sdev and turning the values into percentages gives the scree plot, and here PC1 holds about 92% of the variation. Sorting the loading scores by absolute value names the genes that push samples to the left and to the right.

The main idea

PCA takes many measurements per sample and draws a picture that shows which samples are alike. Here each sample is measured on 100 genes, so each sample is a point in 100 dimensions. PCA finds new axes, called principal components, that carry as much of the spread as possible. The first two axes usually make a readable 2D plot.

In R the whole job is one call to prcomp. The only care you need is the shape of your data. By default prcomp reads rows as samples and columns as variables. Gene data usually arrives the other way round, with samples in columns and genes in rows, so you transpose it with t. If you skip that step you get a plot of how the genes relate to each other, which is not the question here.

The result object holds three parts. x gives the coordinates you plot. sdev gives the standard deviation along each component, which turns into the scree plot. rotation gives the loading scores, which say how much each gene contributed to each component.

Step by step

  1. Build a fake data set: 10 samples measured on 100 genes. Five samples are wild type (normal) and five are knockout (a gene removed).
  2. Transpose the matrix and call prcomp, so that samples sit in rows.
  3. Plot the first two columns of pca$x. That is the PCA plot.
  4. Square pca$sdev, turn the values into percentages, and draw the scree plot to see how much each component is worth.
  5. Redraw the plot with ggplot2 so the points carry sample names and the axes carry the percentages.
  6. Read pca$rotation to find the genes with the largest effect on where samples land.

1. Make the data

Each gene gets fake read counts drawn from a Poisson distribution, with a different mean for the wild type and knockout groups. The details of the biology do not matter; you will bring your own data.

data.matrix <- matrix(nrow=100, ncol=10)
colnames(data.matrix) <- c(paste("wt", 1:5, sep=""), paste("ko", 1:5, sep=""))
rownames(data.matrix) <- paste("gene", 1:100, sep="")

for (i in 1:100) {
  wt.values <- rpois(5, lambda=sample(x=10:1000, size=1))
  ko.values <- rpois(5, lambda=sample(x=10:1000, size=1))
  data.matrix[i,] <- c(wt.values, ko.values)
}
head(data.matrix)     # samples are columns, genes are rows

In Python you would build the same array with numpy.random.poisson and wrap it in a pandas.DataFrame.

2. Run the PCA and draw the plot

Transpose first, then call prcomp. The first two columns of x are the coordinates of the ten samples on PC1 and PC2.

pca <- prcomp(t(data.matrix), scale=TRUE)
plot(pca$x[,1], pca$x[,2], xlab="PC1", ylab="PC2")

The same thing in Python. Scikit-learn centres the data but does not scale it, so put a StandardScaler in front to match scale=TRUE. Rows must already be samples, so no transpose is needed if your frame is in that shape.

import numpy as np, matplotlib.pyplot as plt
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

X = df.T.values                      # rows = samples, cols = genes
Xs = StandardScaler().fit_transform(X)
pca = PCA()                          # keeps all components
scores = pca.fit_transform(Xs)       # same role as pca$x in R

plt.scatter(scores[:, 0], scores[:, 1])
plt.xlabel("PC1"); plt.ylabel("PC2")

3. Check how much each component is worth

The sdev values are standard deviations, so square them to get variances. Divide by the total and multiply by 100 to get percentages, then draw the bar chart.

pca.var <- pca$sdev^2
pca.var.per <- round(pca.var/sum(pca.var)*100, 1)
barplot(pca.var.per, main="Scree Plot",
        xlab="Principal Component", ylab="Percent Variation")

The same thing in Python. Scikit-learn already divides for you, so explained_variance_ratio_ replaces the squaring and the division.

per = np.round(pca.explained_variance_ratio_ * 100, 1)
plt.bar(range(1, len(per) + 1), per)
plt.xlabel("Principal Component"); plt.ylabel("Percent Variation")

4. A nicer plot with ggplot2

ggplot2 wants a data frame with one row per sample. Build it from the sample names and the first two columns of x, then paste the percentages into the axis labels.

library(ggplot2)
pca.data <- data.frame(Sample=rownames(pca$x), X=pca$x[,1], Y=pca$x[,2])

ggplot(data=pca.data, aes(x=X, y=Y, label=Sample)) +
  geom_text() +
  xlab(paste("PC1 - ", pca.var.per[1], "%", sep="")) +
  ylab(paste("PC2 - ", pca.var.per[2], "%", sep="")) +
  theme_bw() +
  ggtitle("My PCA Graph")

The same thing in Python. Matplotlib has no geom_text, so you annotate each point with its sample name.

for name, (x, y) in zip(df.columns, scores[:, :2]):
    plt.annotate(name, (x, y))
plt.xlabel(f"PC1 - {per[0]}%"); plt.ylabel(f"PC2 - {per[1]}%")
plt.title("My PCA Graph")

5. Find the genes that matter

The loading scores live in rotation, one column per component. Take the PC1 column, sort by absolute value so that strong pushes in both directions rank high, and read off the top ten names.

loading_scores <- pca$rotation[,1]
gene_scores <- abs(loading_scores)
gene_score_ranked <- sort(gene_scores, decreasing=TRUE)
top_10_genes <- names(gene_score_ranked[1:10])

pca$rotation[top_10_genes, 1]   # positive push right, negative push left

The same thing in Python. The loadings sit in components_, but transposed: row 0 is PC1 and each column is a gene.

import pandas as pd
loadings = pd.Series(pca.components_[0], index=df.index)
top_10 = loadings.abs().sort_values(ascending=False).head(10).index
loadings[top_10]

Formulas

Variance of a component
$$ \mathrm{Var}_i = (\mathrm{sdev}_i)^2 $$

Symbols: \(\mathrm{sdev}_i\) is the standard deviation that prcomp reports for principal component \(i\). What it tells you: squaring turns the spread along that component into a variance, which is the quantity you can add up across components.

Percent variation per component
$$ \mathrm{pct}_i = 100 \times \frac{(\mathrm{sdev}_i)^2}{\sum_{j=1}^{10} (\mathrm{sdev}_j)^2} $$

Symbols: the top is the variance of component \(i\); the bottom adds the variances of all ten components. What it tells you: the share of the original variation that this component accounts for, which is the height of its bar in the scree plot.

Ranking the loading scores
$$ \text{rank genes by } \left| r_{g,1} \right| $$

Symbols: \(r_{g,1}\) is the loading score of gene \(g\) on PC1, the value in pca$rotation[g, 1]. What it tells you: the size says how strongly the gene moves samples along PC1, and the sign says which side it moves them to.

Worked example from the video

Example

The data set has 10 samples and 100 genes: wt1 to wt5 and ko1 to ko5. After the transpose, prcomp sees 10 rows and 100 columns, so it returns 10 principal components.

Plotting pca$x[,1] against pca$x[,2] puts five samples on one side and five on the other. On its own that picture proves nothing, because any data can be split somehow. The scree plot settles it: PC1 accounts for about 92% of the variation, so almost all of the difference between the samples runs along that left-to-right axis. The gap between the two clusters is therefore a big, real difference.

Because PC1 carries 92%, only its loading scores are worth reading. Sorting the 100 genes by abs(pca$rotation[,1]) and taking the top ten gives the genes with the largest effect on the plot. Among those ten, the ones with positive scores push the KO samples to the right, and the ones with negative scores push the WT samples to the left.

Common mistakes and subtle points

Watch out

Forgetting the transpose is the classic error. prcomp treats rows as samples, so a gene-by-sample matrix passed straight in gives you a plot of genes, not samples. The code still runs and the graph still looks fine, which is what makes this mistake easy to miss.

Watch out

Do not read a PCA plot without its scree plot. Two clean clusters mean little if PC1 only holds a small share of the variation. Here PC1 holds 92%, so the clusters are worth trusting.

Watch out

Sort loading scores by absolute value, not from high to low. Sorting from high to low returns only the genes that push samples one way and hides the equally important genes that push the other way.

Watch out

Scaling differs between the two languages. R's prcomp only scales when you pass scale=TRUE, and scikit-learn's PCA never scales at all. If you want the same answer in Python, run StandardScaler first.

If they ask you in an interview

Why do you transpose the matrix before calling prcomp?
Because prcomp expects one row per sample and one column per variable. Gene expression data usually arrives the other way round, with samples in columns. If you do not transpose, you get a PCA of the genes instead of the samples, and the plot answers a question you did not ask.
How do you decide whether a PCA plot is meaningful?
I look at the percent variation for each component before I read the picture. I square the standard deviations, turn them into percentages, and draw a scree plot. If the first two components carry most of the variation, the 2D picture is a fair summary. In this example PC1 alone carried about 92%, so a wide gap along PC1 is a real difference.
What are loading scores and how do you use them?
Loading scores say how much each original variable contributed to a principal component. In R they are in pca$rotation, one column per component. I sort them by absolute value to find the variables with the biggest effect, then look at the signs to see which side of the plot each one pushes samples toward.
How many principal components can you get?
You never get more than the number of samples, whatever the number of variables. In this example there are 10 samples and 100 genes, and PCA returns 10 components. They come out ordered, with the first holding the most variation and each later one holding less.
