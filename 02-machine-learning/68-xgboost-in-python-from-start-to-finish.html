XGBoost in Python from Start to Finish

▶ Watch on YouTube

Josh walks through a full Jupyter notebook that predicts customer churn with XGBoost. It covers cleaning, missing data, one-hot encoding, early stopping, grid search, and reading the final tree.

In one breath

The data is the IBM Telco churn data set, where the goal is to predict who stops using the company's service. Josh removes columns that leak the answer or carry no information, sets blank values to zero, and one-hot encodes the categories. He splits the data with stratification because only 27% of customers left. A first XGBoost model catches only 51% of the people who left. After tuning with cross-validated grid search, including the scale_pos_weight setting for imbalanced data, the final model catches 84% of them.

The main idea

Most of the work in a real project is getting the data into the right shape. XGBoost only accepts int, float, and boolean columns. So every text column must be checked, cleaned, and turned into numbers before any tree is built.

XGBoost has one unusual strength here. It has a default way to handle missing data. You only need to find the missing values and set them to zero. When the trees are built, XGBoost decides which branch the missing values should follow.

The second theme is class imbalance. This means one class is much rarer than the other. Only 27% of customers left, so a default model does well on people who stay and poorly on people who leave. Josh fixes this with stratified splitting, the AUC as the score, and a penalty for misclassifying the rare class.

Step by step

  1. Load the modules, read the file into a data frame called df, and look at the first five rows. The data has 33 columns.

    import pandas as pd
import numpy as np
import xgboost as xgb
from sklearn.model_selection import train_test_split, GridSearchCV
from sklearn.metrics import plot_confusion_matrix

df = pd.read_csv('Telco_customer_churn.csv')
df.head()   # 5 rows x 33 columns

  2. Drop the last four columns. They come from exit interviews with people who already left, so they would give perfect predictions that are not possible in practice.

    df.drop(['Churn Label', 'Churn Score', 'CLTV', 'Churn Reason'],
        axis=1, inplace=True)

  3. Drop columns that cannot help. Count, Country, and State hold one value each. CustomerID is different for every person, and Lat Long repeats the separate latitude and longitude columns. City has many values, so it stays.

    df['Count'].unique()     # [1]
df['Country'].unique()   # ['United States']
df['State'].unique()     # ['California']

df.drop(['CustomerID', 'Count', 'Country', 'State', 'Lat Long'],
        axis=1, inplace=True)   # 24 columns left

  4. Replace spaces with underscores in the city names and the column names. XGBoost does not care about spaces, but the tree drawing at the end fails with them.

    df['City'].replace(' ', '_', regex=True, inplace=True)
df.columns = df.columns.str.replace(' ', '_')

  5. Look for missing data. Total_Charges looks numeric but has type object. Converting it gives an error that says it cannot parse a blank space, and 11 rows hold that blank.

    df.dtypes
df['Phone_Service'].unique()   # ['Yes', 'No']
# pd.to_numeric(df['Total_Charges'])  -> Unable to parse string " "
len(df.loc[df['Total_Charges'] == ' '])   # 11

  6. All 11 people have zero tenure months, so they have not been charged yet. Set their total charges to zero, convert the column to numbers, and replace any other spaces in the whole data frame.

    df.loc[(df['Total_Charges'] == ' '), 'Total_Charges'] = 0
df.loc[df['Tenure_Months'] == 0]        # check the fix
df['Total_Charges'] = pd.to_numeric(df['Total_Charges'])   # float64
df.replace(' ', '_', regex=True, inplace=True)

  7. Split the columns. Capital X holds the features used to predict, and lowercase y holds Churn_Value, which is 1 for people who left.

    X = df.drop('Churn_Value', axis=1).copy()
y = df['Churn_Value'].copy()

  8. One-hot encode the categorical columns with get_dummies. Each category becomes its own column of ones and zeros. The result has 1,178 columns, mostly because every city gets a column.

    X_encoded = pd.get_dummies(X, columns=['City', 'Gender', 'Senior_Citizen',
    'Partner', 'Dependents', 'Phone_Service', 'Multiple_Lines',
    'Internet_Service', 'Online_Security', 'Online_Backup',
    'Device_Protection', 'Tech_Support', 'Streaming_TV',
    'Streaming_Movies', 'Contract', 'Paperless_Billing',
    'Payment_Method'])
y.unique()   # [1, 0]

  9. Josh then explains how zeros for missing data work with one-hot encoding. Imagine a favourite colour column: two people like blue, two like green, and two are missing. After encoding, the missing people have zero in both the blue and green columns.

    XGBoost compares two splits. One separates blue from everyone else, so missing joins green. The other separates green, so missing joins blue. It keeps the split with the best gain. Because XGBoost stores a sparse matrix, it keeps only the ones, so the zeros cost no memory.

  10. Check the imbalance, then split with stratify=y. This keeps 27% of people who left in both the training and the testing sets.

    sum(y) / len(y)   # 0.27
X_train, X_test, y_train, y_test = train_test_split(
    X_encoded, y, random_state=42, stratify=y)
sum(y_train) / len(y_train)   # 0.27
sum(y_test) / len(y_test)     # 0.27

  11. Build a first model with early stopping. XGBoost trains on the training set. It scores each new tree on the testing set with the AUC, the area under the ROC curve. It stops when 10 more trees bring no improvement, and the best result came at 45 trees.

    clf_xgb = xgb.XGBClassifier(objective='binary:logistic', missing=None, seed=42)
clf_xgb.fit(X_train, y_train,
            verbose=True,
            early_stopping_rounds=10,
            eval_metric='auc',
            eval_set=[(X_test, y_test)])

  12. Draw the confusion matrix on the testing set. The model is right for 1,178 of 1,294 people who stayed, but for only 239 of 467 people who left.

    plot_confusion_matrix(clf_xgb, X_test, y_test,
                      values_format='d',
                      display_labels=["Did not leave", "Left"])

  13. Tune the hyperparameters, the settings you choose by hand, with cross-validated grid search. Josh tries three values each for tree depth, learning rate, gamma, lambda, and scale_pos_weight. Gamma encourages pruning, and lambda is the regularization penalty. Each tree uses a random subset of rows and half the columns, and scoring uses the AUC with 3-fold cross-validation.

    param_grid = {
    'max_depth': [3, 4, 5],
    'learning_rate': [0.1, 0.01, 0.05],
    'gamma': [0, 0.25, 1.0],
    'reg_lambda': [0, 1.0, 10.0],
    'scale_pos_weight': [1, 3, 5]
}
optimal_params = GridSearchCV(
    estimator=xgb.XGBClassifier(objective='binary:logistic', seed=42,
                                subsample=0.9, colsample_bytree=0.5),
    param_grid=param_grid,
    scoring='roc_auc',
    cv=3)
optimal_params.fit(X_train, y_train)
print(optimal_params.best_params_)

  14. Build the final model with the tuned values. Early stopping still picks the number of trees: it stops at 65, and the best was 55.

    clf_xgb = xgb.XGBClassifier(seed=42, objective='binary:logistic',
                            gamma=0.25, learning_rate=0.1, max_depth=4,
                            reg_lambda=10, scale_pos_weight=3,
                            subsample=0.9, colsample_bytree=0.5)
clf_xgb.fit(X_train, y_train, verbose=True, early_stopping_rounds=10,
            eval_metric='auc', eval_set=[(X_test, y_test)])

  15. Draw one tree by setting n_estimators=1, and print its weight, gain, and cover. These numbers suggest sensible ranges for tuning. The root asks if Contract_Month-to-month < 1, and the "yes, missing" branch goes left.

    clf_xgb = xgb.XGBClassifier(seed=42, objective='binary:logistic',
                            gamma=0.25, learning_rate=0.1, max_depth=4,
                            reg_lambda=10, scale_pos_weight=3,
                            subsample=0.9, colsample_bytree=0.5,
                            n_estimators=1)
clf_xgb.fit(X_train, y_train)

bst = clf_xgb.get_booster()
for t in ('weight', 'gain', 'cover'):
    print(t, bst.get_score(importance_type=t))
xgb.to_graphviz(clf_xgb, num_trees=0, size="10,10")

Formulas

This coding video has no model equations, only three small calculations.

Share of customers who left
$$ \text{share left} = \frac{\sum_{i=1}^{n} y_i}{n} \approx 0.27 $$

Symbols: \(y_i\) is 1 if customer \(i\) left and 0 if not; \(n\) is the number of customers. What it tells you: because \(y\) is only ones and zeros, its sum counts the leavers, so this shows how imbalanced the data is.

Share of one row classified correctly
$$ \text{share correct} = \frac{\text{correct predictions in the row}}{\text{people in the row}} $$

Symbols: a row of the confusion matrix is all the people with one true class. What it tells you: how well the model does on each class alone, which matters when one class is rare.

Early stopping
$$ T_{\text{best}} = T_{\text{stop}} - 10 $$

Symbols: \(T_{\text{stop}}\) is the tree count when training stops; 10 is early_stopping_rounds; \(T_{\text{best}}\) is the tree count with the best testing AUC. What it tells you: training stops only after 10 trees in a row fail to improve the AUC.

Worked example from the video

Example

First model. Of 1,294 people who did not leave, 1,178 were correct: \(1178/1294 \approx 0.91\). Of 467 people who left, only 239 were correct: \(239/467 \approx 0.51\). The best result came at 45 trees, and training stopped 10 trees later.

Tuning. Round one gave max_depth 4, the middle value, and gamma 0.25, also the middle. Learning rate and lambda landed on the edge of their ranges, so round two tried larger values. The final values were gamma 0.25, learning rate 0.1, max depth 4, lambda 10, and scale_pos_weight 3.

Final model. Training stopped at 65 trees, so \(65 - 10 = 55\) trees were kept. Now 390 of 467 leavers are correct: \(390/467 \approx 0.84\), up from 0.51. Josh accepts more errors on people who stay. A free milkshake coupon sent to a loyal customer costs less than a lost customer.

Common mistakes and subtle points

Watch out Columns filled in after the outcome, such as exit interview answers, leak the answer. Only people who left have them, so drop them before you build the model.
Watch out An object type on a column that looks numeric often hides blanks or placeholders. Josh checks the fix with zero tenure months, not zero total charges, because some real customers may already have zero charges.
Watch out If grid search picks a value on the edge of a range, the best value may lie beyond it. Search again in that direction. A value in the middle can be fixed for the next round.
Watch out Zero now means both "missing" and "not this category". Josh shows it still works, and notes that the XGBoost author says performance holds up.

If they ask you in an interview

How does XGBoost handle missing values?
It has a default behaviour for missing data, so I just set missing values to zero. At each split, XGBoost tries sending the missing values down each branch and keeps the choice with the best gain. It stores the data as a sparse matrix, so the zeros do not use memory.
Why one-hot encode instead of numbering the categories?
If I code payment methods as 1 to 4, the trees treat 4 as closer to 3 than to 1. That makes them more likely to group credit card with bank transfer for no real reason. One-hot encoding makes each category its own column, so no category is closer to another.
How did you deal with the imbalanced churn data?
Only 27% of customers left, so I split with stratification to keep that share in both sets. I scored with the AUC and tuned scale_pos_weight, which adds a penalty for misclassifying the rare class. That raised correct calls for leavers from 51% to 84%, at some cost on people who stayed.
What does early stopping do?
It adds trees while checking a score, here the AUC, on held-out data. If 10 more trees bring no improvement, it stops and keeps the best number of trees. That means I do not have to tune the number of trees in the grid search.

Recap in 30 seconds

  • Drop columns that leak the answer, hold one value, or are unique for every row.
  • Find hidden blanks by checking data types, then set missing values to zero for XGBoost.
  • One-hot encode categories, because XGBoost only accepts int, float, and boolean columns.
  • Split with stratification when the classes are imbalanced, here 27% left.
  • Early stopping picks the number of trees by stopping after 10 trees without improvement.
  • Grid search with cross-validation and scale_pos_weight lifted correct calls for leavers from 51% to 84%.
