Sequence-to-Sequence (seq2seq) Encoder-Decoder Neural Networks

▶ Watch on YouTube Also in: Neural Networks / Deep Learning (video 18)

This video shows how an encoder-decoder model built from LSTMs turns one sequence into another, using the English sentence "Let's go" translated into the Spanish "Vamos". It matters because this model is a stepping stone to transformers, which power large language models like ChatGPT.

In one breath

A sequence-to-sequence problem turns a sequence of one kind of thing into a sequence of another kind. The two sequences can have different lengths. The encoder runs the input tokens through an embedding layer and unrolled LSTMs. Its final long and short-term memories form the context vector. The decoder starts its own LSTMs from the context vector and begins with the <EOS> token. A fully connected layer and SoftMax pick each output word. Each word is fed back in until the decoder predicts <EOS> or hits a maximum length. During training, teacher forcing feeds in the known correct words and stops at the known length.

The main idea

Josh opens with two problems. Statsquatch wants to translate "Let's go" into Spanish. The Normalsaurus wants to turn a sequence of amino acids into 3D structures like alpha helices. Both take a sequence of one type of thing and produce a sequence of another type. These are called sequence-to-sequence, or seq2seq, problems.

Translation has three length problems. English sentences come in different lengths, Spanish sentences come in different lengths, and a translation can be a different length from its source. The two-word "Let's go" becomes the one-word "Vamos". So the model must handle variable input length and variable output length.

LSTMs (long short-term memory networks) already handle variable lengths, because we can unroll them once per token. An encoder-decoder model uses one set of LSTMs to read the input and a separate set to write the output. The only link between the two halves is the context vector, which is the encoder's final memories.

Step by step

  1. Embed the input tokens. We cannot put words straight into a neural network, so an embedding layer turns each one into numbers. The English vocabulary is "let's", "to", "go" and the symbol <EOS> (end of sentence). Because it mixes words and symbols, each element is called a token. Each token gets two embedding values.
  2. Unroll an LSTM over the sentence. For "Let's go", we put a 1 in the input for "let's" and 0 elsewhere. Then we unroll the LSTM and embedding layer and do the same for "go". Every unrolled copy reuses the exact same weights and biases.
  3. Add more cells. To get more weights and biases to fit the data, people add LSTM cells. Here there are two cells, and both embedding values go into both cells. Each cell has its own weights and biases, which it reuses when unrolled.
  4. Add more layers. A second LSTM layer takes the short-term memories (hidden states) from the first layer as its inputs. Both outputs from layer 1 go into both cells of layer 2. The long and short-term memories are then initialised, and the encoder is done: two layers with two cells each.
  5. Form the context vector. The encoder turns the input sentence into a collection of long and short-term memories, also called cell and hidden states. The last cell and hidden states from both layers are called the context vector.
  6. Start the decoder. The context vector initialises the memories of a new set of LSTMs, again two layers with two cells each. These decoder LSTMs have their own weights and biases, separate from the encoder.
  7. Embed Spanish tokens. The decoder has its own embedding layer for "ir", "vamos", "y" and <EOS>. It has different tokens and different weights from the encoder's embedding layer. Decoding starts with <EOS>, because the original paper did that. Some people use SOS (start of sentence) instead.
  8. Pick the output word. The top layer's two outputs go into a fully connected layer, which is just a basic vanilla neural network. It has two inputs and four outputs, one per Spanish token. A SoftMax function then picks the output word, which is "Vamos".
  9. Feed the prediction back in. The decoder does not stop until it outputs <EOS>. So "vamos" goes into the unrolled embedding layer, the LSTMs unroll, and the same fully connected layer predicts <EOS>. In practice the decoder stops at <EOS> or at a maximum output length.
  10. Train with backpropagation and teacher forcing. All weights and biases are trained with backpropagation. During training the decoder gets the known correct token as input, not its own prediction. It also stops at the length of the known phrase.

Formulas

The video uses no equations. It explains the model with diagrams and sizes. The two rules below just restate, in symbols, what Josh says about the context vector and the output layer.

What the context vector holds
$$ \text{context vector} = \big(c^{(1)},\ h^{(1)},\ c^{(2)},\ h^{(2)}\big)_{\text{last input token}} $$

Symbols: \(c^{(\ell)}\) is the long-term memory (cell state) of LSTM layer \(\ell\). \(h^{(\ell)}\) is the short-term memory (hidden state) of that layer. The superscripts 1 and 2 are the two encoder layers, read after the last input token. What it tells you: the whole input sentence reaches the decoder only through these final memories, which initialise the decoder's LSTMs.

Size of the fully connected output layer
$$ n_{\text{in}} = \text{cells in the top decoder layer}, \qquad n_{\text{out}} = |V_{\text{out}}| $$

Symbols: \(n_{\text{in}}\) is the number of inputs to the fully connected layer. \(n_{\text{out}}\) is its number of outputs. \(|V_{\text{out}}|\) is the number of tokens in the output vocabulary. What it tells you: there is one output per possible output token, and SoftMax picks among them. In the toy model this is 2 inputs and 4 outputs. In the original paper it is 1,000 inputs and 80,000 outputs.

Worked example from the video

Example

Translate "Let's go" into Spanish.

Encoder. "Let's" and then "go" pass through the embedding layer (two values each) and the two LSTM layers of two cells. The final cell and hidden states from both layers form the context vector.

Decoder, step 1. The context vector initialises the decoder LSTMs. The input is <EOS>. The top layer's two outputs go through the fully connected layer (2 inputs, 4 outputs) and SoftMax. The output is "Vamos".

Decoder, step 2. "Vamos" is fed back into the unrolled embedding layer and LSTMs. The same fully connected layer now predicts <EOS>, so decoding stops.

Result. Two English tokens became one Spanish word, "Vamos". Separating the encoder from the decoder is what lets the lengths differ.

Common mistakes and subtle points

Watch out The encoder and decoder do not share weights. They have separate LSTMs and separate embedding layers with different tokens. Sharing only happens within each part, where every unrolled copy reuses the same weights and biases.
Watch out The context vector is not one hidden state. It is the last long and short-term memories (cell and hidden states) from every encoder layer.
Watch out Training and use behave differently. When translating, the decoder feeds back its own predictions until <EOS> or a maximum length. When training with teacher forcing, it feeds in the known correct tokens and stops at the known length.

If they ask you in an interview

How does an encoder-decoder model handle inputs and outputs of different lengths?
Both halves are LSTMs, which can be unrolled once per token, so each side handles any length. The encoder turns the input into a context vector, and the decoder keeps generating until it predicts an end-of-sentence token or hits a maximum length. Because the two halves are decoupled, "Let's go" can become the single word "Vamos".
What is the context vector?
It is the last long and short-term memories, the cell and hidden states, from all the encoder's LSTM layers. It is how the encoder passes the input sentence to the decoder. The decoder uses it to initialise its own LSTMs.
How does the decoder choose each output word?
The top LSTM layer's outputs go into a fully connected layer with one output per token in the output vocabulary. A SoftMax function then picks the word. That word is fed back in as the next input, starting from an <EOS> token at the first step.
What is teacher forcing?
During training, we feed the decoder the known correct token at each step instead of its own prediction. So even if it wrongly predicts "y", the next input is still "Vamos". We also stop at the length of the known phrase, rather than waiting for the model to predict end of sentence.

Recap in 30 seconds

  • Seq2seq problems turn one sequence into another, and the lengths can differ.
  • The encoder embeds each input token and runs it through unrolled, stacked LSTMs that reuse their weights at every step.
  • The last cell and hidden states from all encoder layers form the context vector.
  • The context vector initialises a separate set of decoder LSTMs with their own embedding layer.
  • The decoder starts with <EOS>, and a fully connected layer plus SoftMax picks each output token.
  • Each predicted token is fed back in until the decoder predicts <EOS> or reaches a maximum length.
  • Training uses backpropagation with teacher forcing: known tokens as inputs, stopping at the known length.
