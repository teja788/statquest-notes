Random Forests Part 1 - Building, Using and Evaluating

▶ Watch on YouTube

A single decision tree fits its own data very well, but it is not flexible with new samples. This video shows how many varied trees, built and combined in a simple way, fix that problem.

In one breath

You build each tree from a bootstrap sample, which is a random draw of rows with repeats allowed. At every split you let only a random subset of the columns compete. You repeat this hundreds of times, so the trees end up different from each other. To label a new sample you run it down every tree and take the label with the most votes. Rows left out of a bootstrap sample give you a free accuracy check, called the out-of-bag error.

The main idea

Decision trees are easy to build, easy to use and easy to read. Josh quotes The Elements of Statistical Learning on their weak point: trees are not accurate enough to be the ideal tool. They work great on the data used to create them. They are not flexible when they meet new samples.

A random forest keeps the simplicity of a tree but adds flexibility, and accuracy improves a lot. The trick is variety. Each tree sees a different set of rows and a different set of candidate columns. So each tree makes different mistakes. One tree alone may be wrong, but many varied trees, voting together, are usually right.

Step by step

  1. Make a bootstrap data set. Randomly pick rows from the original data until you have a new set of the same size. You are allowed to pick the same row more than once, so repeats are normal.
  2. Grow a tree from it, but hide most columns at each split. At the root, pick a random subset of the columns and let only those compete. Use the winner to split, then repeat the random pick at the next node.
  3. Repeat hundreds of times. Each round makes a fresh bootstrap sample and a fresh tree. The video shows six trees only because of space.
  4. Use the forest by voting. Run the new sample down every tree and keep the label with the most votes. Bootstrapping the data plus using the aggregate to decide is called bagging.
  5. Score the forest with the left-out rows. About one third of the rows never enter a given bootstrap sample. Those rows are the out-of-bag data set for that tree.
  6. Tune the number of columns per split. Build forests with different settings, compare their out-of-bag errors, and keep the most accurate one.

The out-of-bag check costs nothing extra. Each left-out row goes through the trees built without it, and they vote. If the winning label matches the truth, the row counts as correct.

Formulas

Majority vote
$$ \hat{y}(x) \;=\; \operatorname*{arg\,max}_{c} \sum_{b=1}^{B} \mathbf{1}\{\,T_b(x) = c\,\} $$

Symbols: \(x\) is the new sample's measurements. \(T_b(x)\) is the label that tree number \(b\) gives it. \(B\) is how many trees are in the forest. \(c\) is one possible label, such as yes or no. \(\mathbf{1}\{\cdot\}\) is 1 when the statement inside is true and 0 when it is false. \(\operatorname{arg\,max}_c\) means "the label \(c\) with the largest count". What it tells you: the forest simply counts how many trees chose each label and keeps the winner.

Why about one third is left out
$$ P(\text{a row never gets picked}) = \left(1 - \frac{1}{n}\right)^{n} \;\longrightarrow\; \frac{1}{e} \approx 0.37 $$

Symbols: \(n\) is the number of rows in the original data. \(1/n\) is the chance that one draw picks a chosen row, so \(1-1/n\) is the chance it misses. The exponent \(n\) is there because we draw \(n\) times. \(e \approx 2.718\) is Euler's number. What it tells you: as the data grows, roughly 37 percent of rows sit outside each bootstrap sample. That is the "about one third" that Josh mentions.

Out-of-bag error
$$ \text{OOB error} = \frac{\text{out-of-bag samples labelled wrong}}{\text{all out-of-bag samples}}, \qquad \text{accuracy} = 1 - \text{OOB error} $$

Symbols: the top counts left-out rows whose majority vote disagrees with the true label. The bottom counts every left-out row that was tested. What it tells you: it estimates how well the forest handles data it has not seen, without holding back a separate test set.

Columns to try at each split
$$ m \approx \sqrt{p} $$

Symbols: \(m\) is how many columns compete at one split. \(p\) is the total number of columns in the data. What it tells you: the square root is only a starting point. Josh advises trying a few values above and below it, and keeping the one with the lowest out-of-bag error.

Worked example from the video

Example

Josh uses a tiny heart disease data set of four patients and four columns. Two of the columns he names are good blood circulation and blocked arteries. He admits the size is crazy small, but it makes every step visible.

Bootstrap. He draws four rows at random with repeats allowed. The fourth draw happens to be the same row as the third, so one row appears twice and one row never appears at all.

Split the root. Josh lets only two of the four columns compete at each step. The random pick gives good blood circulation and blocked arteries. He assumes good blood circulation separates the patients best, so it becomes the root. He greys it out to focus on the three remaining columns.

Split the next node. Again only two of the three remaining columns are drawn as candidates. The rest of the tree is built as usual, with a fresh random pick at each step.

Vote. A new patient arrives with all measurements. Tree one says yes, and tree two also says yes. After every tree votes, yes has the most votes. So the forest concludes that this patient has heart disease.

Check. The left-out row goes through the trees built without it. One tree wrongly says yes, but most say no, which is correct. So the forest labels this out-of-bag sample correctly.

Common mistakes and subtle points

Watch out The random subset of columns is drawn again at every split, not once per tree. If you pick the columns only at the root, the trees stay far too similar and you lose the variety that makes the forest work.
Watch out The bootstrap sample must be the same size as the original and must allow repeats. Sampling without replacement would just return the same data every time, so every tree would look alike.
Watch out A left-out row is judged only by the trees that never saw it. Letting every tree vote on it would reuse training data. That would make your accuracy look better than it is.

If they ask you in an interview

Why is a random forest more accurate than a single decision tree?
A single tree fits its training data closely but is not flexible with new samples. A forest builds many trees from different bootstrap samples. Each split also sees only a random subset of columns. So the trees differ, and the majority vote is more accurate than any one tree.
What is out-of-bag error, and why is it useful?
About a third of the rows never enter a given bootstrap sample. Each such row goes through only the trees built without it, and they vote. The share of these rows labelled wrong is the out-of-bag error. It estimates accuracy on new data without a separate test set.
How do you choose how many columns to consider at each split?
I treat it as a setting to tune. I start at the square root of the number of columns. Then I try a few values above and below it. I keep the setting with the lowest out-of-bag error.
What is bagging, and is it the same as a random forest?
Bagging means bootstrapping the data and then using the aggregate to make a decision. A random forest adds one more step. At each split, only a random subset of columns may compete. That extra randomness makes the trees more varied.

Recap in 30 seconds

  • Decision trees are simple, but they are not flexible with new samples.
  • A bootstrap sample draws rows at random, with repeats, until it matches the original size.
  • Each tree uses its own bootstrap sample and a random subset of columns at each split.
  • Hundreds of such trees give a wide variety, and variety brings the accuracy gain.
  • A new sample gets the label with the most votes across all trees.
  • Bootstrapping plus aggregating the votes is called bagging.
  • The rows left out of each bootstrap sample give a free accuracy estimate, the out-of-bag error.
  • Start with the square root of the number of columns per split, then tune it.
