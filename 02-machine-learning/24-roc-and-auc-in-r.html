ROC and AUC in R

▶ Watch on YouTube

Josh draws ROC graphs in R with the pROC package. He makes the graph readable, pulls out the thresholds behind one part of the curve, shades a partial area, and compares two models on one plot.

In one breath

This lesson is the hands-on twin of the earlier ROC and AUC video. Josh builds 100 fake samples of weight and obesity, fits a logistic regression, and feeds the true labels and the predicted probabilities into the roc function. A few arguments turn the default plot into a clean graph. Saving the roc output gives a table of true positive rate, false positive rate and threshold. He then shades a partial AUC, and adds a random forest curve on top for comparison.

The main idea

An ROC graph summarises a classifier at every threshold. A threshold is the cut-off probability above which you call a sample positive. Each threshold gives one true positive rate and one false positive rate, and that pair is one dot on the graph.

In R you do not build this by hand. The roc function in the pROC package takes the known classes and the predicted probabilities. It walks through every threshold, records both rates, draws the curve, and prints the area under it. That area, the AUC, is one number between 0 and 1, so it lets you compare two models quickly.

The figure below shows what the roc function returns. Notice the two ends of the curve, because they explain the first and last rows of the table you get back.

Step by step

  1. Load pROC for the graphs and randomForest for the second model.
  2. Set the seed to 420, then build 100 weights and their obese labels.
  3. Fit a logistic regression with glm and draw the fitted curve.
  4. Call roc with the labels and the fitted probabilities, then fix the cosmetics.
  5. Save the roc output to read the thresholds behind any part of the curve.
  6. Shade a partial AUC, then add a random forest curve for comparison.

Build the example data and fit the model

The weights come from a normal distribution and are sorted. The label is random, but heavier samples are much more likely to be obese, because the rank sets the probability.

library(pROC)
library(randomForest)

set.seed(420)
num.samples <- 100
weight <- sort(rnorm(n = num.samples, mean = 172, sd = 29))

# heavier samples get a higher chance of being called obese
obese <- ifelse(test = runif(n = num.samples) < (rank(weight) / num.samples),
                yes = 1, no = 0)

plot(x = weight, y = obese)

glm.fit <- glm(obese ~ weight, family = binomial)
lines(weight, glm.fit$fitted.values)

The same thing in Python, with numpy and scikit-learn.

import numpy as np
import matplotlib.pyplot as plt
from scipy.stats import rankdata
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(420)
weight = np.sort(rng.normal(172, 29, size=100))
obese = (rng.random(100) < rankdata(weight) / 100).astype(int)

model = LogisticRegression(penalty=None).fit(weight.reshape(-1, 1), obese)
probs = model.predict_proba(weight.reshape(-1, 1))[:, 1]   # like glm.fit$fitted.values

Draw the ROC graph and make it readable

The roc function needs the true labels and the estimated probabilities. Everything after that is presentation.

par(pty = "s")            # square plot region, no ugly side padding

roc(obese, glm.fit$fitted.values, plot = TRUE,
    legacy.axes = TRUE,   # x axis is 1 - specificity, left to right
    percent = TRUE,       # axes in percentages, not 0 to 1
    xlab = "False Positive Percentage",
    ylab = "True Positive Percentage",
    col = "#377eb8", lwd = 4,
    print.auc = TRUE)

In Python you compute the points with roc_curve, get the area with roc_auc_score, and draw the graph yourself.

from sklearn.metrics import roc_curve, roc_auc_score

fpr, tpr, thresholds = roc_curve(obese, probs)
auc = roc_auc_score(obese, probs)

plt.figure(figsize=(5, 5))
plt.plot(fpr * 100, tpr * 100, color="#377eb8", lw=4)
plt.plot([0, 100], [0, 100], "k--", lw=1)
plt.xlabel("False Positive Percentage")
plt.ylabel("True Positive Percentage")
plt.title(f"AUC = {auc:.3f}")

Read the thresholds behind a piece of the curve

Store the result instead of only plotting it. It holds the sensitivities, the specificities and the thresholds, which you can put in a data frame.

roc.info <- roc(obese, glm.fit$fitted.values, legacy.axes = TRUE)

roc.df <- data.frame(
  tpp = roc.info$sensitivities * 100,           # true positive percentage
  fpp = (1 - roc.info$specificities) * 100,     # false positive percentage
  thresholds = roc.info$thresholds)

head(roc.df)   # threshold -Inf: tpp 100, fpp 100  (top right corner)
tail(roc.df)   # threshold  Inf: tpp   0, fpp   0  (bottom left corner)

# the thresholds behind the part of the curve with tpp between 60 and 80
roc.df[roc.df$tpp > 60 & roc.df$tpp < 80, ]

In Python, roc_curve already returns the same three vectors.

import pandas as pd

roc_df = pd.DataFrame({"tpp": tpr * 100, "fpp": fpr * 100, "thresholds": thresholds})
roc_df.head()
roc_df.tail()
roc_df[(roc_df.tpp > 60) & (roc_df.tpp < 80)]

Shade a partial AUC

A partial AUC looks only at the part of the curve where false positives are rare. The range is in specificity, so 100 to 90 means the first ten percent of the x axis.

roc(obese, glm.fit$fitted.values, plot = TRUE, legacy.axes = TRUE, percent = TRUE,
    xlab = "False Positive Percentage", ylab = "True Positive Percentage",
    col = "#377eb8", lwd = 4,
    print.auc = TRUE, print.auc.x = 45,
    partial.auc = c(100, 90),      # specificity range, not 1 - specificity
    auc.polygon = TRUE,
    auc.polygon.col = "#377eb822") # the last two digits make it transparent

In Python, roc_auc_score takes max_fpr, and fill_between shades the region.

partial = roc_auc_score(obese, probs, max_fpr=0.1)   # McClish-standardised
plt.fill_between(fpr[fpr <= 0.1] * 100, tpr[fpr <= 0.1] * 100,
                 color="#377eb8", alpha=0.2)

Compare two models on one graph

Draw the first curve, then add the second one with plot.roc and add = TRUE. Move the second AUC text down so the two numbers do not overlap.

rf.model <- randomForest(factor(obese) ~ weight)

roc(obese, glm.fit$fitted.values, plot = TRUE, legacy.axes = TRUE, percent = TRUE,
    xlab = "False Positive Percentage", ylab = "True Positive Percentage",
    col = "#377eb8", lwd = 4, print.auc = TRUE)

plot.roc(obese, rf.model$votes[, 1], percent = TRUE, add = TRUE,
         col = "#4daf4a", lwd = 4, print.auc = TRUE, print.auc.y = 40)

legend("bottomright", legend = c("Logistic Regression", "Random Forest"),
       col = c("#377eb8", "#4daf4a"), lwd = 4)

par(pty = "m")   # back to the default, maximum plot area

In Python, plot both curves on the same axes.

from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(random_state=420).fit(weight.reshape(-1, 1), obese)
rf_probs = rf.predict_proba(weight.reshape(-1, 1))[:, 1]
rf_fpr, rf_tpr, _ = roc_curve(obese, rf_probs)

plt.plot(fpr * 100, tpr * 100, color="#377eb8", lw=4,
         label=f"Logistic Regression, AUC = {roc_auc_score(obese, probs):.3f}")
plt.plot(rf_fpr * 100, rf_tpr * 100, color="#4daf4a", lw=4,
         label=f"Random Forest, AUC = {roc_auc_score(obese, rf_probs):.3f}")
plt.legend(loc="lower right")

Formulas

The two axes
$$ \text{TPR} = \frac{TP}{TP + FN}, \qquad \text{FPR} = \frac{FP}{FP + TN} = 1 - \text{specificity} $$

Symbols: \(TP\) is true positives, \(FN\) false negatives, \(FP\) false positives, \(TN\) true negatives. TPR is also called sensitivity. What it tells you: the y axis is the share of real positives you caught, and the x axis is the share of real negatives you wrongly flagged.

The two columns of roc.df
$$ \text{tpp} = 100 \times \text{sensitivities}, \qquad \text{fpp} = 100 \times (1 - \text{specificities}) $$

Symbols: sensitivities and specificities are vectors inside the object that roc returns, one entry per threshold. What it tells you: this is what percent = TRUE and legacy.axes = TRUE do, written out by hand.

Area under the curve
$$ \text{AUC} = \int_{0}^{1} \text{TPR}\,d(\text{FPR}) $$

Symbols: the integral runs over the whole x axis. What it tells you: one number for the whole curve. A perfect model gives 1, the diagonal chance line gives 0.5.

Partial area under the curve
$$ \text{pAUC} = \int_{0}^{0.1} \text{TPR}\,d(\text{FPR}) \quad\text{for}\quad \text{specificity} \in [90\%, 100\%] $$

Symbols: the upper limit 0.1 is the largest false positive rate you accept. What it tells you: how good the model is when false positives are expensive. In R you set partial.auc = c(100, 90), in specificity units.

Worked example from the video

Example

The data set has 100 samples instead of the eight used in the earlier ROC video. The weights use mean 172 and standard deviation 29, the real figures for men's weight in pounds.

The label comes from the rank. The lightest sample has rank 1, so its scaled rank is \(1/100 = 0.01\). The heaviest has rank 100, so its scaled rank is 1. Each sample is called obese when a random number between 0 and 1 is smaller than its scaled rank. So light samples are mostly zeros and heavy samples are mostly ones.

When you call roc, R prints three things. It echoes your call, counts how many samples are not obese and how many are obese, and prints the AUC.

In roc.df, the first row has a threshold of \(-\infty\). Every sample is then called obese, so both percentages are 100. That row is the top right corner. The last row has a threshold of \(+\infty\), every sample is called not obese, both percentages are 0, and that row is the bottom left corner.

Filtering to rows with a true positive percentage between 60 and 80 gives the thresholds behind that piece of the curve. From those you pick the one with the best balance for your problem.

Common mistakes and subtle points

Watch out By default roc puts specificity on the x axis, so it runs from 1 on the left to 0 on the right. That backwards axis is easy to misread. Set legacy.axes = TRUE.
Watch out The partial.auc argument is given in specificity, not in 1 minus specificity. So c(100, 90) means the leftmost ten percent of the graph.
Watch out For the random forest, Josh passes rf.model$votes[, 1], the share of trees that voted for a class. An ROC curve always needs a continuous score, never a hard 0 or 1 prediction.
Watch out par(pty = "s") is a global setting. Every later plot stays square until you set it back with par(pty = "m").

If they ask you in an interview

How do you draw an ROC curve and get the AUC in R?
I use the pROC package. I pass the known labels and the predicted probabilities to roc with plot = TRUE, and it draws the curve and prints the AUC. I add legacy.axes = TRUE so the x axis is 1 minus specificity. In Python I use roc_curve and roc_auc_score from scikit-learn, then plot with matplotlib.
Someone gives you an ROC curve and asks for a threshold. How do you find it?
The curve alone does not show thresholds, so I save the object roc returns. It holds the sensitivities, the specificities and the matching thresholds. I put them into a data frame and filter to the region I want, for example a true positive rate between 60 and 80 percent. Then I pick the threshold with the best balance for the cost of each error.
What is a partial AUC and when would you use it?
A partial AUC is the area under only part of the curve, usually the part with very few false positives. I use it when a false positive is expensive. Two models can have the same full AUC but behave very differently in that corner. In pROC I set partial.auc with a specificity range, and in scikit-learn I use max_fpr.
How do you compare two classifiers with ROC curves?
I draw both curves on the same axes. In R I plot the first with roc, then add the second with plot.roc and add = TRUE, and I move the second AUC label with print.auc.y. Then I check whether one curve is above the other everywhere, or whether they cross. If they cross, I compare partial AUCs over the threshold range I care about.

Recap in 30 seconds

  • The pROC package draws ROC graphs from two vectors: the true labels and the predicted probabilities.
  • Use par(pty = "s") for a square plot, and reset it with par(pty = "m") afterwards.
  • Set legacy.axes = TRUE so the x axis is 1 minus specificity, and percent = TRUE for percentage scales.
  • Save the roc output to get the sensitivities, specificities and thresholds behind every point.
  • The first row of that table is the top right corner and the last row is the bottom left corner.
  • A partial AUC focuses on the low false positive corner, and its range is given in specificity.
  • Add a second curve with plot.roc and add = TRUE to compare two models on one graph.
