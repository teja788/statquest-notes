Support Vector Machines in Python from Start to Finish.

▶ Watch on YouTube Also in: —

Josh builds a support vector classifier in Python, step by step, to predict whether a person will default on a credit card. The video shows the full path from a raw file to a tuned model and a picture of its decision surface.

In one breath

The data is the UCI credit card default data set, with 30,000 customers. Josh removes 68 rows with missing values and downsamples to 1,000 people who defaulted and 1,000 who did not. He one-hot encodes the categorical columns, splits the data into training and testing sets, and scales it. A default scikit-learn SVC (support vector classifier) does all right, but not great. GridSearchCV then finds C = 100 and gamma = 0.001, which helps only a little. Finally, PCA squeezes the data into two dimensions so he can draw an approximate decision surface.

The main idea

Josh says support vector machines are one of the best choices when a correct answer matters more than knowing why the answer is correct. They work well with relatively small data sets. They also tend to work well out of the box, so they need little optimization.

Most of the work in this video is data preparation, not modelling. The SVM in scikit-learn cannot handle missing values or raw categorical codes. Josh uses the radial basis function (RBF), a kernel that scores how close two points are. The RBF assumes each column is centered and scaled, which means mean 0 and standard deviation 1. So the pipeline has to clean, shrink, encode, and scale the data before any fitting happens. After that, fitting and tuning take only a few lines of code.

Step by step

  1. Import the modules. Pandas loads the data and does one-hot encoding, NumPy handles arrays, and Matplotlib draws graphs. Scikit-learn provides the SVM, the data splitting, the scaling, and the confusion matrix. 
    import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
from sklearn.utils import resample
from sklearn.model_selection import train_test_split, GridSearchCV
from sklearn.preprocessing import scale
from sklearn.svm import SVC
from sklearn.metrics import plot_confusion_matrix
from sklearn.decomposition import PCA
  2. Load and tidy the data. The file is tab-delimited, and the header is on the second row. Josh renames the long target column to DEFAULT and drops ID, because random ID numbers carry no information. 
    df = pd.read_csv('default_of_credit_card_clients.tsv', header=1, sep='\t')
df.rename({'default payment next month': 'DEFAULT'}, axis='columns', inplace=True)
df.drop('ID', axis=1, inplace=True)
  3. Find and remove missing data. Every column is int64, but the allowed values tell a different story. EDUCATION should hold 1 to 4 but also has 0, 5 and 6, and MARRIAGE should hold 1 to 3 but also has 0. Josh treats 0 as missing, counts 68 such rows, and keeps the rest. 
    len(df.loc[(df['EDUCATION'] == 0) | (df['MARRIAGE'] == 0)])   # 68
df_no_missing = df.loc[(df['EDUCATION'] != 0) & (df['MARRIAGE'] != 0)]
len(df_no_missing)                                               # 29932
  4. Downsample. SVMs can take a long time on large data sets, and 29,932 rows is relatively large. Josh splits the data by class and samples 1,000 rows from each class without replacement, then joins them back together. 
    df_no_default = df_no_missing[df_no_missing['DEFAULT'] == 0]
df_default    = df_no_missing[df_no_missing['DEFAULT'] == 1]
df_no_default_downsampled = resample(df_no_default, replace=False, n_samples=1000, random_state=42)
df_default_downsampled    = resample(df_default,    replace=False, n_samples=1000, random_state=42)
df_downsample = pd.concat([df_no_default_downsampled, df_default_downsampled])   # 2000 rows
  5. Split into X and y. By convention, capital X holds the columns used to make classifications. Lowercase y holds the thing to predict. 
    X = df_downsample.drop('DEFAULT', axis=1).copy()
y = df_downsample['DEFAULT'].copy()
  6. One-hot encode the categorical columns. SEX, EDUCATION, MARRIAGE and the PAY columns are categories. The pandas function get_dummies() turns each one into several 0/1 columns, one per category. 
    X_encoded = pd.get_dummies(X, columns=['SEX', 'EDUCATION', 'MARRIAGE',
                                       'PAY_0', 'PAY_2', 'PAY_3', 'PAY_4', 'PAY_5', 'PAY_6'])
  7. Split into training and testing sets, then scale. The radial basis function assumes each column has mean 0 and standard deviation 1. Josh does not scale y, because it is only 0s and 1s. 
    X_train, X_test, y_train, y_test = train_test_split(X_encoded, y, random_state=42)
X_train_scaled = scale(X_train)
X_test_scaled  = scale(X_test)
  8. Build a preliminary SVM. SVC() makes an untrained shell of a support vector classifier, and fit() trains it. A confusion matrix is a table of correct and wrong predictions for each class. Josh draws one for the test set. 
    clf_svm = SVC(random_state=42)
clf_svm.fit(X_train_scaled, y_train)
plot_confusion_matrix(clf_svm, X_test_scaled, y_test, values_format='d',
                      display_labels=["Did not default", "Defaulted"])
  9. Tune C and gamma with cross validation. Optimizing an SVM is mostly about finding the best gamma, and maybe the regularization parameter C. Gamma sets how far the influence of one point reaches in the RBF. C sets how strongly the model is penalized for misclassified training points. GridSearchCV tries every combination in a grid and scores each one with cross validation. Josh sticks with the radial basis function, because other kernels take a long time and RBF usually gives the best performance. 
    param_grid = [{'C': [0.5, 1, 10, 100],        # values for C must be > 0
               'gamma': ['scale', 1, 0.1, 0.01, 0.001, 0.0001],
               'kernel': ['rbf']}]
optimal_params = GridSearchCV(SVC(), param_grid, cv=5, scoring='accuracy')
optimal_params.fit(X_train_scaled, y_train)
print(optimal_params.best_params_)   # C = 100, gamma = 0.001
  10. Build and evaluate the final SVM. The code is the same as before, but with the tuned values. A new confusion matrix compares it with the preliminary model. 
    clf_svm = SVC(random_state=42, C=100, gamma=0.001)
clf_svm.fit(X_train_scaled, y_train)
plot_confusion_matrix(clf_svm, X_test_scaled, y_test, values_format='d',
                      display_labels=["Did not default", "Defaulted"])
  11. Draw the decision surface with PCA. The data has 24 columns, so a true picture would need 24 or more dimensions. PCA (principal component analysis) combines columns into a few new ones that keep most of the variation. A scree plot shows how much variation each new column keeps. Josh uses PCA to shrink the data to two columns and checks a scree plot. Then he re-tunes and retrains an SVM on just those two columns and draws its decision surface. 
    pca = PCA()
X_train_pca = pca.fit_transform(X_train_scaled)
per_var = np.round(pca.explained_variance_ratio_ * 100, decimals=1)   # heights for the scree plot

pca_train_scaled = scale(np.column_stack((X_train_pca[:, 0], X_train_pca[:, 1])))
optimal_params.fit(pca_train_scaled, y_train)   # new best C and gamma for 2-D data

Formulas

The video has no derivations. Two simple rules sit under the code.

Centering and scaling one column
$$ z_i = \frac{x_i - \bar{x}}{s} $$

Symbols: \(x_i\) is one value in a column, \(\bar{x}\) is the column mean, \(s\) is the column standard deviation, and \(z_i\) is the scaled value. What it tells you: after this step every column has mean 0 and standard deviation 1, which is what the radial basis function assumes.

Percent correct in one row of the confusion matrix
$$ \text{percent correct} = \frac{\text{correctly classified in the row}}{\text{total people in the row}} \times 100 $$

Symbols: a row holds all test people with the same true class, for example the 257 people who did not default. What it tells you: how well the model does for each class on its own, which is how Josh reads the 79% and 61%.

Worked example from the video

Example

Missing data. 68 of 30,000 rows have a 0 in EDUCATION or MARRIAGE. That is \(68 / 30{,}000 \approx 0.23\%\), which is less than 1%. So Josh removes them, and \(30{,}000 - 68 = 29{,}932\) rows remain.

Preliminary model. The test set has 257 people who did not default and 243 who did, 500 in total. 79% of 257 is about 203 correct. 61% of 243 is about 148 correct. Overall, about \((203 + 148) / 500 \approx 70\%\) are correct.

Tuned model. GridSearchCV picks C = 100 and gamma = 0.001. Four more people are correctly classified as not defaulting, and one more person who defaulted is misclassified. So the tuned model is only a little better, or even a little worse if the defaulters matter more.

Common mistakes and subtle points

Watch out Do not treat category codes as continuous numbers. If MARRIAGE stays as 1, 2, 3, the SVM assumes "other" (3) is closer to "single" (2) than to "married" (1). One-hot encoding makes every category equally different from the others.
Watch out Treating 0 as missing is a guess. The data description does not explain 0, 5 or 6 in EDUCATION. Josh tried both ways, and the classifier did better when 0 was treated as missing.
Watch out Josh believes the default split is 70% training and 30% testing, but he says not to quote him. The test set in his confusion matrix has 257 + 243 = 500 people, which is 25% of 2,000.
Watch out The PCA picture is only an approximation. You want the first two bars of the scree plot to be much taller than the rest. Here only the first bar stands out, so the decision surface looks messy.

If they ask you in an interview

Why do you one-hot encode categorical features before fitting an SVM?
The scikit-learn SVM supports continuous data natively, but not categorical data. If I leave codes like 1, 2, 3 as numbers, the model thinks 3 is closer to 2 than to 1. One-hot encoding gives each category its own 0/1 column, so no category is more similar to any other.
Why do you scale the data, and what do you scale?
The radial basis function assumes each column is centered and scaled, with mean 0 and standard deviation 1. I scale the feature columns in the training and test sets. I do not scale the target, because it is just 0s and 1s.
How did you tune the SVM, and did it help?
I used GridSearchCV with five-fold cross validation over values of C and gamma, with the RBF kernel. C is the regularization parameter and must be greater than zero. The best values were C = 100 and gamma = 0.001. The gain was small, which is common because SVMs tend to work well out of the box.
Why downsample to 2,000 rows?
SVMs work well on relatively small data sets but can take a long time on large ones. Cross validation over a grid multiplies that cost. Taking 1,000 people from each class kept the grid search reasonably fast and gave equal class sizes.
How can you draw a decision boundary when the data has 24 columns?
I use PCA to shrink the data to two principal components and retrain an SVM on just those two. I check the scree plot first, because the picture is only trustworthy if the first two components are much taller than the rest. In this data only the first one stood out, so the picture was a rough approximation.

Recap in 30 seconds

  • Most of the work in an SVM project is getting the data into the right format.
  • Zeros in EDUCATION and MARRIAGE were treated as missing, and those 68 rows were removed.
  • The data was downsampled to 1,000 defaulters and 1,000 non-defaulters, because SVMs are slow on large data.
  • Categorical columns were one-hot encoded with get_dummies(), and the features were centered and scaled.
  • The default RBF SVC classified 79% of non-defaulters and 61% of defaulters correctly.
  • GridSearchCV chose C = 100 and gamma = 0.001, which changed only a few predictions.
  • PCA to two components gives a picture of the decision surface, but a weak scree plot means the picture is only approximate.
