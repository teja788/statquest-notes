Long Short-Term Memory with PyTorch + Lightning

▶ Watch on YouTube Also in: Neural Networks / Deep Learning (video 31)

Josh codes a long short-term memory (LSTM) unit by hand in PyTorch and trains it with Lightning. Then he rebuilds the same model in a few lines with nn.LSTM. Along the way he shows how to log training, graph it in TensorBoard, and add more epochs without starting over.

In one breath

The task is to predict day 5 of two companies' stock prices from days 1 to 4. The only clue is day 1, so the LSTM must remember it. Josh codes the weights, the three LSTM stages and the forward pass inside one Lightning class. He trains it for 2,000 epochs, then resumes up to 3,000 and finally 5,000. TensorBoard graphs of the loss and the two predictions tell him when the curves flatten and training can stop. Finally, nn.LSTM with a larger learning rate solves the same problem in only 300 epochs.

The main idea

The data comes from the earlier LSTM video. Company A and Company B have the same stock values on days 2, 3 and 4. They differ only on day 1 and day 5. Company A is 0 on both days, and Company B is 1 on both days. So the LSTM has to carry the day 1 value through its memory to predict day 5.

An LSTM unit keeps two memories. The long-term memory is a running value that passes through with few changes. The short-term memory is the unit's output at each step. Each step has three stages, and every stage uses its own weights and bias on the short-term memory and the current input.

Step by step

  1. Imports. Josh imports torch, torch.nn, torch.nn.functional, the Adam optimizer, lightning as L, and TensorDataset and DataLoader. Adam is a lot like SGD but not quite as stochastic, so it tends to find the optimal values faster.
  2. Class plan. The class LSTMbyHand inherits from L.LightningModule. It has five methods: __init__, lstm_unit, forward, configure_optimizers and training_step.
  3. Initialise parameters. Each weight starts as a random draw from a normal distribution with mean 0 and standard deviation 1. In Josh's run the first two weights came out as 0.34 and 0.13. Every bias starts at 0, and all of them have requires_grad=True so they get optimised.
  4. Code the LSTM math. lstm_unit takes an input value, the long-term memory and the short-term memory. It runs the three stages in the figure and returns the updated long and short memories.
  5. Unroll in forward. forward sets both memories to 0, splits the four days into variables, and calls lstm_unit once per day. This is called unrolling: the same unit, with the same weights, is reused for each day. It returns the final short-term memory as the prediction.
  6. Optimizer and loss. configure_optimizers returns Adam. training_step predicts, computes the squared residual, and logs it as train_loss. It also logs the prediction as out_0 for Company A or out_1 for Company B.
  7. Train and check. A Trainer with max_epochs=2000 fits the model. An epoch is one pass through both companies. TensorBoard, a tool that graphs the log files, shows whether the loss and predictions have flattened out.
  8. Resume from a checkpoint. A checkpoint is a saved copy of the model during training. Lightning saves them, so Josh adds epochs without starting over: first up to 3,000, then up to 5,000. After that the curves flatten.
  9. Use nn.LSTM. A second class, LightningLSTM, replaces all the hand-written math with one call to nn.LSTM. With a learning rate of 0.1 it trains well in 300 epochs.

Here is the start of __init__. The other weights and biases follow the same pattern.

class LSTMbyHand(L.LightningModule):
    def __init__(self):
        super().__init__()
        mean = torch.tensor(0.0)
        std = torch.tensor(1.0)
        self.wlr1 = nn.Parameter(torch.normal(mean=mean, std=std), requires_grad=True)
        self.wlr2 = nn.Parameter(torch.normal(mean=mean, std=std), requires_grad=True)
        self.blr1 = nn.Parameter(torch.tensor(0.), requires_grad=True)
        # ... same for the other weights and biases

This is the LSTM math. Each line matches one box in the first figure.

    def lstm_unit(self, input_value, long_memory, short_memory):
        long_remember_percent = torch.sigmoid((short_memory * self.wlr1) + (input_value * self.wlr2) + self.blr1)
        potential_remember_percent = torch.sigmoid((short_memory * self.wpr1) + (input_value * self.wpr2) + self.bpr1)
        potential_memory = torch.tanh((short_memory * self.wp1) + (input_value * self.wp2) + self.bp1)
        updated_long_memory = (long_memory * long_remember_percent) + (potential_remember_percent * potential_memory)
        output_percent = torch.sigmoid((short_memory * self.wo1) + (input_value * self.wo2) + self.bo1)
        updated_short_memory = torch.tanh(updated_long_memory) * output_percent
        return [updated_long_memory, updated_short_memory]

The forward pass unrolls the unit over four days. The other two methods set the optimizer and the logged loss.

    def forward(self, input):
        long_memory = 0
        short_memory = 0
        day1, day2, day3, day4 = input[0], input[1], input[2], input[3]
        long_memory, short_memory = self.lstm_unit(day1, long_memory, short_memory)
        long_memory, short_memory = self.lstm_unit(day2, long_memory, short_memory)
        long_memory, short_memory = self.lstm_unit(day3, long_memory, short_memory)
        long_memory, short_memory = self.lstm_unit(day4, long_memory, short_memory)
        return short_memory

    def configure_optimizers(self):
        return Adam(self.parameters())

    def training_step(self, batch, batch_idx):
        input_i, label_i = batch
        output_i = self.forward(input_i[0])
        loss = (output_i - label_i)**2
        self.log("train_loss", loss)
        if label_i == 0:
            self.log("out_0", output_i)
        else:
            self.log("out_1", output_i)
        return loss

The training data is one row of four days per company, with the day 5 values as labels.

inputs = torch.tensor([[0., 0.5, 0.25, 1.], [1., 0.5, 0.25, 1.]])
labels = torch.tensor([0., 1.])
dataset = TensorDataset(inputs, labels)
dataloader = DataLoader(dataset)

model = LSTMbyHand()
trainer = L.Trainer(max_epochs=2000)
trainer.fit(model, train_dataloaders=dataloader)

To add more epochs, take the latest checkpoint path, make a new trainer with the new total, and pass the path to fit.

path_to_best_checkpoint = trainer.checkpoint_callback.best_model_path
trainer = L.Trainer(max_epochs=3000)   # 2000 done + 1000 more
trainer.fit(model, train_dataloaders=dataloader, ckpt_path=path_to_best_checkpoint)

The log calls write files into a folder called lightning_logs. From a terminal in the folder that holds it, run this command and open the URL it prints.

tensorboard --logdir=lightning_logs

With nn.LSTM, the class becomes much shorter. input_size is the number of features, here 1. hidden_size is the number of output values, here 1.

class LightningLSTM(L.LightningModule):
    def __init__(self):
        super().__init__()
        self.lstm = nn.LSTM(input_size=1, hidden_size=1)

    def forward(self, input):
        input_trans = input.view(len(input), 1)
        lstm_out, temp = self.lstm(input_trans)
        prediction = lstm_out[-1]
        return prediction

    def configure_optimizers(self):
        return Adam(self.parameters(), lr=0.1)
    # training_step is the same as before

trainer = L.Trainer(max_epochs=300, log_every_n_steps=2)

Formulas

Weight initialisation
$$ w \sim \mathcal{N}(0,\,1), \qquad b = 0 $$

Symbols: \(w\) is any weight, \(\mathcal{N}(0,1)\) is a normal distribution with mean 0 and standard deviation 1, and \(b\) is any bias. What it tells you: weights start as random numbers that are most likely close to 0, and biases start at exactly 0.

Stage 1: how much long memory to keep
$$ r_{\text{long}} = \sigma\big(w_{lr1}\,s + w_{lr2}\,x + b_{lr1}\big) $$

Symbols: \(s\) is the short-term memory, \(x\) is the input value, the \(w\) and \(b\) terms are this stage's weights and bias, and \(\sigma\) is the sigmoid function, which squashes any number to between 0 and 1. What it tells you: \(r_{\text{long}}\) is the percentage of the long-term memory to remember.

Stage 2: new long-term memory
$$ r_{\text{pot}} = \sigma\big(w_{pr1}\,s + w_{pr2}\,x + b_{pr1}\big), \qquad p = \tanh\big(w_{p1}\,s + w_{p2}\,x + b_{p1}\big) $$ $$ \ell_{\text{new}} = \ell \cdot r_{\text{long}} + r_{\text{pot}} \cdot p $$

Symbols: \(p\) is the potential long-term memory, \(\tanh\) squashes a number to between −1 and 1, \(r_{\text{pot}}\) is the percentage of \(p\) to remember, \(\ell\) is the current long-term memory and \(\ell_{\text{new}}\) is the updated one. What it tells you: the new long-term memory is a scaled copy of the old one plus a scaled piece of the new candidate.

Stage 3: new short-term memory
$$ r_{\text{out}} = \sigma\big(w_{o1}\,s + w_{o2}\,x + b_{o1}\big), \qquad s_{\text{new}} = \tanh(\ell_{\text{new}}) \cdot r_{\text{out}} $$

Symbols: \(r_{\text{out}}\) is the percentage to output, \(\tanh(\ell_{\text{new}})\) is the potential short-term memory, and \(s_{\text{new}}\) is the new short-term memory. What it tells you: the unit's output is a percentage of the squashed long-term memory.

Loss in training_step
$$ \text{loss} = (\text{output}_i - \text{label}_i)^2 $$

Symbols: \(\text{output}_i\) is the predicted day 5 value for one company, and \(\text{label}_i\) is the observed day 5 value (0 or 1). What it tells you: this is the squared residual for one company; each epoch has two such steps, one per company.

Worked example from the video

Example

Company A has days 1 to 4 of 0, 0.5, 0.25 and 1, and its day 5 value is 0. Company B has 1, 0.5, 0.25 and 1, and its day 5 value is 1. The pre-trained LSTM from the earlier video outputs 0.0 for A and 1.0 for B, which is exactly right.

Before training. With random weights, the hand-built model predicts −0.04 for Company A. That is close to the target of 0. It also predicts −0.04 for Company B, which is far from the target of 1. To print these values, Josh calls model(torch.tensor([0., 0.5, 0.25, 1.])).detach().

After 2,000 epochs. Company A is now 0.43, which is worse than at the start. Company B is a little better but still not good. In TensorBoard, the loss is still going down, and Company A's prediction got bad around step 1,000 but has improved since. None of the curves has flattened, so more training should help.

Up to 3,000 epochs. Company A moves closer to 0 and Company B moves closer to 1. The curves still have not flattened.

Up to 5,000 epochs. Company A is really close to 0 and Company B is really close to 1. Every curve in TensorBoard is now flat, so training is done.

nn.LSTM. The starting predictions are far from ideal. With a learning rate of 0.1 instead of the default 0.001, 300 epochs are enough. Company A ends super close to 0 and Company B ends close to 1, and the curves flatten.

Common mistakes and subtle points

Watch out A prediction can get worse before it gets better. After 2,000 epochs Company A went from −0.04 to 0.43. Judge training by whether the TensorBoard curves have flattened, not by one snapshot.
Watch out When you resume, max_epochs is the new total, not the extra amount. To add 1,000 epochs after 2,000, set it to 3,000 and pass the checkpoint path to fit.
Watch out nn.LSTM wants the input as a column, one row per time step. Use view(len(input), 1) so it works for any number of days. Its output holds the short-term memory from every unrolled unit, so take the last one with [-1].
Watch out Lightning writes logs every 50 steps by default. With 300 epochs of 2 steps each, you get only 12 points, so Josh sets log_every_n_steps=2. When comparing runs in TensorBoard, show only the newest version folder so the x-axis is scaled properly.

If they ask you in an interview

Walk me through what one LSTM unit computes.
There are three stages. First, a sigmoid of the short-term memory and input decides what percentage of the long-term memory to keep. Second, a sigmoid and a tanh create a potential memory and decide how much of it to add, which updates the long-term memory. Third, another sigmoid decides what percentage of the tanh of the new long-term memory becomes the new short-term memory.
What does "unrolling" an LSTM mean in code?
It means calling the same unit once per time step, with the same weights each time. In the hand-built version, the forward method starts both memories at zero and calls the unit for days one to four. The final short-term memory is the prediction.
In nn.LSTM, what are input_size and hidden_size?
Input size is the number of features at each time step, which is one here. Hidden size is the number of output values. If you fed the LSTM into another network with three inputs, you would set hidden size to three, and PyTorch would add the extra weights and biases.
How do you know when to stop training, and how do you continue if you have not?
I log the loss and the predictions, then look at them in TensorBoard. If the curves are still moving, I keep training. With Lightning, I take the best model path from the trainer's checkpoint, create a new trainer with a higher max epochs, and pass that path to fit so it continues where it left off.
