PCA in Python

▶ Watch on YouTube

Josh runs a complete PCA in Python, from made-up data to the final graph. The code comes from Chris Yogodzinski, and every line has a job.

In one breath

First you build a small gene expression table with 100 genes and 10 samples. Then you centre and scale the data, and you must transpose it first, because scikit-learn wants samples in rows. The PCA object from scikit-learn does the maths: fit finds the loading scores and the variation per component, and transform makes the graph coordinates. A scree plot shows that almost all the variation sits on PC1, so a PC1 against PC2 plot is enough. The plot separates the two sample groups, and the loading scores for PC1 tell you which genes caused that separation.

The main idea

PCA takes a table with many columns and finds a few new axes that hold most of the variation. Those new axes are the principal components. In Python you get them from the PCA class in scikit-learn.

Python has no built-in tables, random numbers, or graphs, so you import them. Pandas gives you the data frame, NumPy gives you the random numbers and the maths, and Matplotlib draws the plots.

One detail decides whether your result is right or nonsense: the shape of the input. Genomic tables usually store samples as columns, but scikit-learn expects one row per sample. So you transpose the table before you scale it. The figure below shows what that flip does.

Step by step

  1. Import the packages, because Python has no tables, random numbers, or plots on its own.
  2. Build a fake data set of 100 genes across five wild type and five knockout samples.
  3. Transpose the table, then centre and scale it so no gene dominates by size alone.
  4. Create a PCA object, fit it, and transform the scaled data into coordinates.
  5. Draw a scree plot to decide how many principal components matter.
  6. Draw the PC1 against PC2 graph and label each point with its sample name.
  7. Sort the PC1 loading scores by size to find the genes that drove the separation.

Import the packages

The random package is only here to invent example data; real data needs no such thing.

import pandas as pd
import numpy as np
import random as rd
from sklearn.decomposition import PCA
from sklearn import preprocessing
import matplotlib.pyplot as plt

Make the example data

The stars unpack the two name lists into one flat list of column names.

genes = ['gene' + str(i) for i in range(1, 101)]

wt = ['wt' + str(i) for i in range(1, 6)]   # 1, 2, 3, 4, 5
ko = ['ko' + str(i) for i in range(1, 6)]

data = pd.DataFrame(columns=[*wt, *ko], index=genes)

for gene in data.index:
    data.loc[gene, 'wt1':'wt5'] = np.random.poisson(lam=rd.randrange(10, 1000), size=5)
    data.loc[gene, 'ko1':'ko5'] = np.random.poisson(lam=rd.randrange(10, 1000), size=5)

print(data.head())
print(data.shape)      # (100, 10)

Each gene gets its own Poisson mean, drawn between 10 and 1000, so genes differ in size.

Centre and scale

Pass the transpose, then check the shape if you are unsure which way round it is.

scaled_data = preprocessing.scale(data.T)

Do the PCA

Scikit-learn uses an object you fit on one data set and can apply to another.

pca = PCA()                        # create the object
pca.fit(scaled_data)               # loading scores and variation per PC
pca_data = pca.transform(scaled_data)   # coordinates for the graph

The scree plot

This turns the variation ratios into percentages and draws one bar per component.

per_var = np.round(pca.explained_variance_ratio_ * 100, decimals=1)
labels = ['PC' + str(x) for x in range(1, len(per_var) + 1)]

plt.bar(x=range(1, len(per_var) + 1), height=per_var, tick_label=labels)
plt.ylabel('Percentage of Explained Variance')
plt.xlabel('Principal Component')
plt.title('Scree Plot')
plt.show()

The PCA graph

Put the coordinates into a labelled data frame first, so the loop can annotate each point.

pca_df = pd.DataFrame(pca_data, index=[*wt, *ko], columns=labels)

plt.scatter(pca_df.PC1, pca_df.PC2)
plt.title('My PCA Graph')
plt.xlabel('PC1 - {0}%'.format(per_var[0]))
plt.ylabel('PC2 - {0}%'.format(per_var[1]))

for sample in pca_df.index:
    plt.annotate(sample, (pca_df.PC1.loc[sample], pca_df.PC2.loc[sample]))

plt.show()

The loading scores

Principal components are zero indexed, so PC1 is row zero of components_.

loading_scores = pd.Series(pca.components_[0], index=genes)

sorted_loading_scores = loading_scores.abs().sort_values(ascending=False)
top_10_genes = sorted_loading_scores[0:10].index.values

print(loading_scores[top_10_genes])

Formulas

Centre and scale
$$ z_{ij} = \frac{x_{ij} - \bar{x}_j}{s_j} $$

Symbols: \(x_{ij}\) is the count of gene \(j\) in sample \(i\); \(\bar{x}_j\) is the mean of gene \(j\) across the samples; \(s_j\) is its standard deviation; \(z_{ij}\) is the scaled value. What it tells you: after this step every gene has mean zero and standard deviation one, so a loud gene cannot dominate a quiet one.

Two divisors: Python and R
$$ s^2_{\text{sklearn}} = \frac{\sum (x - \bar{x})^2}{n} \qquad s^2_{\text{R}} = \frac{\sum (x - \bar{x})^2}{n - 1} $$

Symbols: \(n\) is the number of measurements; \(x\) is one measurement; \(\bar{x}\) is their mean. What it tells you: R divides by \(n-1\), which gives a larger but unbiased estimate. The loading scores and the percentages per component are the same either way, so only the drawn coordinates shift a little.

Percentage of variation per component
$$ \text{per\_var}_k = 100 \times \frac{\lambda_k}{\sum_m \lambda_m} $$

Symbols: \(\lambda_k\) is the variation held by component \(k\); the sum runs over all components. What it tells you: this is exactly explained_variance_ratio_ turned into a percentage, and it is the height of each scree plot bar.

Where a sample lands on PC1
$$ \text{PC1}_i = \sum_{j=1}^{100} w_j \, z_{ij} $$

Symbols: \(w_j\) is the loading score of gene \(j\) in PC1, from pca.components_[0]; \(z_{ij}\) is the scaled value of that gene in sample \(i\). What it tells you: a coordinate is the loading scores multiplied by the scaled values and added up. That is why a different scaling divisor moves the points slightly.

Worked example from the video

Example

The made-up table has 100 genes and 10 samples, so data.shape prints (100, 10). Five samples are wild type and five are knockout. Every gene gets a fresh Poisson mean between 10 and 1000, drawn once for the wild type group and once for the knockout group.

After the PCA, the scree plot shows almost all the variation on the first principal component. That is the signal to stop at two dimensions: PC1 and PC2 will represent the original data well.

The PCA graph then shows the five wild type samples together on the left and the five knockout samples together on the right. Points that sit together are correlated with each other. The wide gap along the x axis says the two groups are very different.

Finally the top 10 PC1 loading scores come out very similar in size. Josh reads this as many genes sharing the work of separating the groups, rather than one or two genes doing it alone.

Common mistakes and subtle points

Watch out Scikit-learn wants one row per sample. Genomic tables usually store samples as columns, so you pass data.T. If you forget the transpose, you scale samples instead of genes and the whole result is wrong. Nothing warns you, because the code still runs.
Watch out Python counts from zero, so PC1 is pca.components_[0]. It is easy to type [1] and quietly report the second component's loading scores.
Watch out Sort the loading scores by their absolute value. A large negative score matters as much as a large positive one; it only means the gene pushes samples the other way along the axis.
Watch out Python and R use different divisors when they compute variation. The loading scores and the percentage per component agree, but the plotted coordinates differ slightly.

If they ask you in an interview

Why do you centre and scale before PCA?
PCA looks for the directions with the most variation. Without scaling, a variable measured on a large scale looks more important simply because its numbers are bigger. Centring puts every variable's mean at zero and scaling puts every standard deviation at one, so each variable starts on equal terms.
What does a scree plot tell you?
It shows the percentage of variation held by each principal component, in order. You use it to decide how many components to keep. In this example almost everything sits on PC1, so a two dimensional plot of PC1 against PC2 already represents the data well.
What is the difference between fit and transform on a PCA object?
Fit does the actual PCA maths on the data you give it: it finds the loading scores and how much variation each component accounts for. Transform then uses those loading scores to turn data into coordinates. Keeping them apart lets you fit on training data and transform new data with the same components.
How do you find which variables drive the separation?
You look at the loading scores for the component that separates the groups, here PC1. Put them in a pandas Series indexed by variable name, sort by absolute value, and read off the top few. If those top scores are all similar, many variables share the effect rather than one dominating.
Two samples sit close together on the PCA graph. What does that mean?
It means their values are correlated across the measured variables, so the components score them almost the same. In this example the wild type samples cluster on one side and the knockout samples on the other. The distance between the two clusters along PC1 is the real finding.
