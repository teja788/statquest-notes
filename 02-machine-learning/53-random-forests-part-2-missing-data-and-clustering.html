Random Forests Part 2: Missing data and clustering

▶ Watch on YouTube

A random forest can fill in missing values on its own. The same machinery also measures how similar any two samples are, so a forest can cluster data.

In one breath

Josh handles two kinds of missing data: gaps in the data you train on, and gaps in a new sample you want to classify. For the first kind you make a rough first guess, then improve it. The improvement uses a proximity matrix, which counts how often two samples land in the same leaf. Higher proximity means more similar, so one minus proximity is a distance. That distance lets you draw a heat map or an MDS plot from any kind of data.

The main idea

The data set has four patients. Patient four is missing two values: blocked arteries and weight. Random forests treat this differently from a gap in a brand new sample, so Josh separates the two cases.

For a gap in the training data the plan is simple. Make an initial guess that may be bad. Then refine the guess again and again until it stops changing. The refinement needs to know which other patients look like patient four.

Similarity in a random forest has an unusual definition. Two samples are similar if they fall into the same leaf node when you run them down a tree. Do that for every tree and count the hits. The counts live in a proximity matrix, one row and one column per sample.

Step by step

  1. Look at the outcome label of the sample with the gap. Patient four does not have heart disease, so only the other patients without heart disease are used for the first guess.
  2. For the categorical value, take the most common value among those patients. Two out of two say "no" for blocked arteries, so the first guess is "no".
  3. For the numeric value, take the median of those patients. Here the median weight is 167.5, so that becomes the first guess.
  4. Build a random forest on the data set with the guesses filled in.
  5. Run every sample down every tree. Two samples that stop at the same leaf node are treated as similar.
  6. Add 1 to the proximity matrix for each pair that shared a leaf, once per tree. In the video, samples 3 and 4 shared a leaf in trees one, two and three, and sample 2 joined them in tree two.
  7. Divide every entry by the number of trees. With 10 trees the entries become proportions between 0 and 1.
  8. Revise the guesses with those proportions, then repeat the whole loop. Josh runs it six or seven times, until the filled-in values stop changing.

Proximity is also a distance

Imagine samples 3 and 4 shared a leaf in all 10 trees. Their proximity would be 1, the largest value possible. So proximity 1 means no distance at all, and proximity 0 means far apart. Subtract each proximity from 1 and you have a distance matrix. From that you can draw a heat map or an MDS plot. An MDS plot places similar samples close together on a flat map. This works whatever the data are: ranks, multiple choice, or numbers. If you can build a tree from it, you can cluster it.

A gap in a new sample

Now the forest already exists and a new patient arrives with blocked arteries missing. You cannot run the patient down the trees without that value. So you make two copies of the patient, one labelled as having heart disease and one labelled as not having it. Fill each copy with the iterative method above, then run both down all the trees. The copy that the forest labels correctly more often wins.

Formulas

Initial guess
$$ \hat{x}_{\text{cat}} = \text{mode}\{x_i : y_i = y_m\} \qquad \hat{x}_{\text{num}} = \text{median}\{x_i : y_i = y_m\} $$

Symbols: \(x_i\) is the value of that column for sample \(i\); \(y_i\) is that sample's outcome label; \(y_m\) is the outcome label of the sample with the gap; mode is the most common value. What it tells you: the first guess ignores everything except the outcome label, so it is quick and often wrong.

Proximity
$$ p_{ij} = \frac{1}{T}\sum_{t=1}^{T} \mathbf{1}\big[L_t(i) = L_t(j)\big] $$

Symbols: \(T\) is the number of trees; \(L_t(i)\) is the leaf node that sample \(i\) reaches in tree \(t\); \(\mathbf{1}[\cdot]\) is 1 when the statement is true and 0 when it is false. What it tells you: the share of trees in which two samples end up together, so \(p_{ij}\) runs from 0 to 1.

Refined guess
$$ \hat{x}_{\text{cat}} = \arg\max_{c} \ \frac{1}{|S_c|}\sum_{i \in S_c} p_{im} \qquad \hat{x}_{\text{num}} = \sum_{i} w_i x_i,\quad w_i = \frac{p_{im}}{\sum_{j} p_{jm}} $$

Symbols: \(m\) is the sample with the gap; \(c\) is one candidate category, such as "yes" or "no"; \(S_c\) is the set of samples that carry category \(c\); \(|S_c|\) is how many there are; \(w_i\) is the share of the total proximity that sample \(i\) holds. What it tells you: similar samples get more say, so the guess moves toward the neighbours the forest trusts.

Distance from proximity
$$ d_{ij} = 1 - p_{ij} $$

Symbols: \(d_{ij}\) is the distance between samples \(i\) and \(j\); \(p_{ij}\) is their proximity. What it tells you: a proximity of 1 gives distance 0, so the matrix can feed a heat map or an MDS plot.

Worked example from the video

Example

After 10 trees, sample 4 has proximity 0.1 with sample 1, 0.1 with sample 2, and 0.8 with sample 3.

Blocked arteries. Only sample 2 says "yes", so the average proximity for yes is 0.1. Samples 1 and 3 say "no", so the average for no is \((0.1 + 0.8) / 2 = 0.45\). No is much larger, so the refined guess stays "no".

Weight. The proximities add up to \(0.1 + 0.1 + 0.8 = 1.0\), so the weights are 0.1, 0.1 and 0.8. Sample 1 weighs 125, sample 2 weighs 180, sample 3 weighs 210. The first-guess median, 167.5, came from samples 1 and 3: \((125 + 210)/2\).

$$ 0.1 \times 125 \;+\; 0.1 \times 180 \;+\; 0.8 \times 210 \;=\; 12.5 + 18 + 168 \;=\; 198.5 $$

The guess moves from the median of 167.5 to 198.5, pulled up by sample 3. Rebuild the forest with these values and run the loop again.

Common mistakes and subtle points

Watch out The first guess uses only the samples that share the outcome label. If you take the mode or median over the whole column, you throw away the strongest clue you have.
Watch out Proximity is not a distance between feature values. It is produced by the trees, so it depends on the forest you built. A different forest gives slightly different proximities.
Watch out One pass is not enough. The forest behind the proximities was itself built on guessed values. So you rebuild and recompute six or seven times, until the values stop changing.
Watch out For a new sample you do not guess the outcome label. You create one copy per possible label, fill each one in, and let the forest decide which copy it reproduces best.

If they ask you in an interview

How does a random forest fill in missing values in the training data?
It starts with a rough guess from samples with the same outcome label. A category gets their most common value, and a number gets their median. Then it builds a forest and measures how close each sample is to the one with the gap. It replaces the guess with a proximity-weighted answer and repeats six or seven times.
What is a proximity matrix?
It has one row and one column per sample. You run every sample down every tree. You add one whenever two samples land in the same leaf. Then you divide by the number of trees, so each entry is a share between 0 and 1.
How can a random forest cluster data?
One minus each proximity gives a distance matrix. Proximity 1 means the samples always shared a leaf, so their distance is zero. You can feed that matrix into a heat map or an MDS plot. It works for any data you can build a tree from, such as ranks or multiple choice.
A new sample arrives with a missing value. What do you do?
I make one copy of the sample for each possible outcome label. I fill in the gap in each copy with the iterative proximity method. Then I run both copies down the forest. The copy that the trees label correctly more often gives both the missing value and the prediction.

Recap in 30 seconds

  • Random forests handle two kinds of missing data: gaps in the training data and gaps in a new sample.
  • For training data you make a rough guess first, using the mode or the median of samples with the same outcome label.
  • You then measure similarity by running all samples down all trees and counting shared leaf nodes.
  • Those counts, divided by the number of trees, form the proximity matrix.
  • You refine a category by comparing average proximities, and a number by taking a proximity-weighted average.
  • In the video the weight guess moves from 167.5 to 198.5 in one pass, and the loop repeats until it converges.
  • One minus proximity is a distance, so any tree-friendly data set can be drawn as a heat map or an MDS plot.
  • For a new sample you test one copy per label and keep the copy the forest classifies correctly most often.
