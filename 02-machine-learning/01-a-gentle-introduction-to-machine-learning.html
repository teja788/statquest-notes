A Gentle Introduction to Machine Learning

▶ Watch on YouTube

This video says what machine learning is for, in the simplest way. It is about making predictions and classifications, and about choosing a method with testing data.

In one breath

Josh shows two toy examples. A decision tree asks a few questions and classifies a person as someone who loves StatQuest or not. A straight line fitted to yam and running speed predicts how fast a new person runs. Both are machine learning, because both make predictions. The main lesson is that we judge any method on new data, called testing data, not on the data used to build it.

The main idea

Josh starts with a silly song that asks three questions. Do you like silly songs? Are you interested in machine learning? Are you interested in statistics? The answers lead to a verdict: you will love StatQuest, or you might not. Those questions and answers form a decision tree, which is a simple machine learning method.

The tree does a job called classification. It puts a person into one of two groups. If you understand how a person walks down this tree and gets a label, you already understand the shape of machine learning.

The second example predicts a number instead of a label. Josh imagines measuring how much yam a person eats and how fast that person runs 100 metres. In the pretend data, people who eat more yam run faster. A straight black line drawn through the points shows the trend. Give the line a new yam amount, and it returns a predicted speed. That is a prediction, and it makes the line a machine learning method too.

Step by step

Josh then uses the yam data to show how we choose between two methods. The order below follows the video.

  1. Call the original data the training data. This is the data we use to build or fit the method.
  2. Fit a simple black line to the training data. It passes near the points but not through them.
  3. Fit a wiggly green curve to the same training data. This green squiggle passes through the points almost perfectly.
  4. Collect data from new people. Measure their yam and their speed. Together these new people are the testing data.
  5. For each new person, read the predicted speed off the black line. Measure the distance between the real speed and the predicted speed. Add these distances up.
  6. Do the same with the green squiggle. Measure each distance and add them up.
  7. Compare the two totals. The smaller total wins, so we keep that method for future predictions.

When Josh does this, the green squiggle has the larger total. The black line fitted the training data worse, but it predicted the testing data better. So the black line is the method we keep.

Formulas

The video shows no algebra, but it does add up distances and count correct answers. These two lines write down exactly what Josh draws.

Total distance on testing data
$$ D \;=\; \sum_{i=1}^{n} \left| y_i - \hat{y}_i \right| $$

Symbols: \(n\) is the number of people in the testing data. \(y_i\) is the real speed of person \(i\). \(\hat{y}_i\) is the speed the method predicts for that person. The bars \(|\cdot|\) mean distance, so the value is never negative. The sign \(\sum\) means add the distances over all testing people. What it tells you: \(D\) is one number that scores a method on new data, and the method with the smaller \(D\) is the better predictor.

Score for a classifier
$$ \text{Accuracy} \;=\; \frac{c}{n} $$

Symbols: \(c\) is the number of testing people the decision tree labelled correctly. \(n\) is the number of people in the testing data. What it tells you: when the method returns a label instead of a number, we count correct labels instead of measuring distances, and the higher fraction wins.

Worked example from the video

Example

Josh uses four people in the testing data for the yam and speed example. For the first person, the black line predicts a slightly slower speed than the real one, so he saves that distance. He repeats this for the second, third and fourth person and keeps a running total:

$$ D_{\text{line}} = d_1 + d_2 + d_3 + d_4 $$

Then he repeats the whole process with the green squiggle and gets a second total:

$$ D_{\text{squiggle}} = g_1 + g_2 + g_3 + g_4 $$

The bars in the video show that \(D_{\text{squiggle}} > D_{\text{line}}\). The squiggle hugged the training points, yet it missed the new points by more. So we pick the black line.

The decision tree is scored the same way. The first testing person disliked silly songs, machine learning and statistics, so the tree said "might not love StatQuest". That person actually loves StatQuest, so the tree was wrong. The second person liked silly songs and machine learning, so the tree said "loves StatQuest", and that was right. After two people the score is \(1/2\), and we keep going down the rest of the testing data.

Common mistakes and subtle points

Watch out A good fit to the training data proves nothing. The green squiggle passed through every training point and still lost. Josh calls this trap the bias-variance tradeoff, and a later StatQuest covers it properly.
Watch out Do not judge a method by how modern or complicated it sounds. Josh points out that a deep learning network and a plain black line are compared in exactly the same way: by how they perform on testing data.
Watch out The split into training and testing data is a real choice, not an afterthought. In the video the red dots were training data only by an arbitrary decision, and the blue dots could have played that role instead. Proper methods for splitting exist, and cross validation is the next video.
Watch out Prediction and classification are different outputs of the same idea. The line returns a number, the tree returns a label, so their scores are computed differently.

If they ask you in an interview

What is machine learning, in one or two sentences?
Machine learning is a set of methods that make predictions and classifications from data. A method is fitted to training data, then judged on testing data it has never seen. Anything from a straight line to a deep network fits that description.
Why not simply keep the model that fits the training data best?
Because fitting the training data is not the goal; predicting new data is. A wiggly curve can pass through every training point and still miss new points badly. That is why we always hold out testing data and compare methods there.
How do you compare two regression models on testing data?
I take each testing point, read off the predicted value, and measure the distance between the real value and the prediction. I add those distances into one total for each model. The model with the smaller total is the better predictor.
Would you ever prefer a simple model over a modern one?
Yes, whenever the simple model scores better on testing data. The name of the method does not decide anything; the testing score does. A simple model is also easier to explain and to maintain, so it is a fair default until something beats it.
How do you decide which rows become training data and which become testing data?
Picking a split by hand is arbitrary, and the answer can change with the split you happen to choose. So I use a systematic scheme such as cross validation, which rotates every block of data through the testing role. That gives a score that does not depend on one lucky split.

Recap in 30 seconds

  • Machine learning is about making predictions and classifications.
  • A decision tree asks a few questions and gives each person a label, which is classification.
  • A line fitted to yam and speed returns a number for a new person, which is prediction.
  • The data used to build a method is called training data.
  • The fresh data used to judge it is called testing data.
  • For numbers, add the distances between real and predicted values, and prefer the smaller total.
  • The green squiggle fitted the training data best but lost on testing data, so the black line was kept.
  • Choose a method by its testing performance, not by how fancy it sounds.
